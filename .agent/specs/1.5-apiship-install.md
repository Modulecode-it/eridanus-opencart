**Задача:** 1.5-apiship-install
**Дата:** 2026-07-29
**Статус:** код подготовлен

## Цель

Установить модуль доставки ApiShip 1.2 (OpenCart 3.x) в проект eridanus-opencart для подключения агрегированной доставки через Яндекс Доставку (и при необходимости другие ТК) с расчётом стоимости в чекауте, выбором ПВЗ и курьерской доставкой, выгрузкой заказов и получением трек-статусов.

## Область

- Установка модуля ApiShip 1.2 как OCMOD-пакета (zip) через Extension Installer либо из исходника в репозитории.
- Размещение исходника пакета `apiship-1.2_3.x.ocmod/` в корне репозитория (по образцу `measoft_oc3.ocmod/`, задача 1.4).
- Анализ совместимости OCMOD `install.xml` с существующими модификаторами (`system/tweak.ocmod.xml`, `system/availpro.ocmod.xml`, `system/simple_twig_fix.ocmod.xml`, `system/__fix_theme_editor.ocmod.xml`).
- Подготовка инструкций по настройке в админке (токен ApiShip, адрес отправителя, провайдеры, статусы, cron).

В область **не входит** (требует доступа к живой админке/серверу/внешним ЛК и выполняется вручную):
- Ввод токена ApiShip и ключа Яндекс.Карт JS в настройках модуля.
- Регистрация/настройка ЛК `apiship.ru`, привязка Яндекс Доставки как провайдера.
- Настройка cron-задач на сервере.
- Вводная HTTP/браузерная проверка витрины (по `STACK.md` проверка сайта — только через git-деплой на сервере).

## Предпосылки от заказчика

- Модуль: `apiship-1.2_3.x.ocmod.zip` (документация `https://docs.apiship.ru/docs/integrations-marketplaces/opencart/install/`).
- Доставка: по РФ в ПВЗ и курьером получателю на адрес по РФ.
- Сдача заказов и приём возвратов — только в ПВЗ по адресу `197373, СПб, Планерная 47`.
- Заказчиком предоставлен OAuth-токен Яндекса вида `y0__***`.

## Требования

1. **R1. Совместимость.** Модуль должен корректно устанавливаться на OpenCart 3.0.3.2 (текущая версия проекта) без ручной правки ядра.
2. **R2. Отсутствие конфликтов OCMOD.** Модификатор `install.xml` модуля не должен конфликтовать по якорям с существующими `.ocmod.xml` проекта; все операции используют `error="skip"`, чтобы невозможность применения операции не роняла витрину/админку.
3. **R3. Повторяемость.** Установка должна быть воспроизводима из репозитория (zip + распакованный исходник в корне), как задача 1.4 (Measoft).
4. **R4. Изоляция токена.** Токен ApiShip и ключ Яндекс.Карт не должны попадать в репозиторий (хранятся в БД через `oc_setting`, читаются модулем через `$this->config->get(...)`).
5. **R5. Покрытие кейса РФ.** Настроиваемые поля модуля должны покрывать: ПВЗ + курьер по РФ, адрес отправителя `197373, СПб, Планерная 47`, маппинг статусов, выгрузка/отмена заказов, групповой экспорт по cron, трек-статусы.

## Ограничения

- Не раскладывать файлы модуля напрямую в `admin/`, `catalog/`, `system/` — проектный паттерн (задача 1.4) хранит модуль как пакет в корне репозитория и ставит через Extension Installer. Это соответствует правилу `STACK.md` «предпочитать исходные файлы / не редактировать сгенерированное».
- Не коммитить токены, креды, полные логи (правило `.agent/RULES.md`).
- Не выполнять локальные HTTP/браузерные запросы к `eridanus.dev.modulecode.ru` (правило `STACK.md`).
- Уточнение у заказчика: предоставленный токен `y0__***` — это OAuth-токень Яндекса (для прямого API `b2b.taxi.yandex.net`), а модуль ApiShip требует **свой** токен из ЛК `apiship.ru`. Это расхождение требует отдельного подтверждения от заказчика (см. «Известные пробелы» в отчёте).

## Критерии приёмки

- A1. В корне репозитория присутствуют `apiship-1.2_3.x.ocmod.zip` и распакованный исходник `apiship-1.2_3.x.ocmod/` с `install.xml` и деревом `upload/`.
- A2. Анализ OCMOD-конфликтов выполнен и зафиксирован в `analysis/`; подтверждено отсутствие пересечений по якорям с tweak/availpro/simple_twig_fix.
- A3. Все якоря `install.xml`, проверенные по реальным файлам проекта, присутствуют (модификатор применится).
- A4. В отчёте зафиксированы ручные шаги: Extensions → Installer → upload zip; Extensions → Modifications → Refresh; Extensions → Shipping → включить ApiShip; заполнение настроек; cron.
- A5. Документация задачи 1.5 создана (spec/analysis/implementation/report), статус в `INDEX.md` обновлён.
- A6. Секреты в репозиторий не попадают.
