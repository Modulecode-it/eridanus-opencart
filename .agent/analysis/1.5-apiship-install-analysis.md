## Текущее поведение

В проекте модуля ApiShip нет. Доставка представлена:
- CDEK (`cdek_integrator`, `shipping/cdek`),
- Measoft (`shipping/measoftcourier`, `shipping/measoftcouriershipping`, задача 1.4 — пакет `measoft_oc3.ocmod.zip` в корне),
- Yandex (`yandex_marketplace`, `yandex_market`, `yaorder/`).

Паттерн установки сторонних модулей доставки в проекте (по задаче 1.4): **модуль хранится в корне репозитория как zip + распакованный исходник `*.ocmod/`**, установка выполняется через Extension Installer админки. Файлы модуля **не** раскладываются по `admin/catalog/system`.

## Что такое ApiShip

ApiShip (`apiship.ru`) — агрегатор доставки: единый API, под которым доступны Яндекс Доставка, СДЭК, Boxberry, DPD, 5Post и др. Модуль OpenCart `apiship-1.2_3.x.ocmod` — метод доставки `extension/shipping/apiship`. Авторизация на `https://api.apiship.ru/v1/` заголовком `Authorization: <apiship_token>` (проверено в `upload/system/library/apiship/apiship.php:40,72`).

**Важно:** ApiShip ≠ прямая Яндекс Доставка. Предоставленный заказчиком токен `y0__***` — OAuth-токень Яндекса для прямого API `b2b.taxi.yandex.net` (`Authorization: Bearer ...`). Для модуля ApiShip он **не подходит**; нужен отдельный токен из ЛК `apiship.ru`. См. «Риски».

## Поток данных

1. **Каталог/чекаут:** покупатель выбирает город → `catalog/model/extension/shipping/apiship.php` через `system/library/apiship/apiship.php` делает `GET/POST https://api.apiship.ru/v1/...` с заголовком `Authorization: <apiship_token>` → возвращает тарифы ПВЗ/курьера → OCMOD-патчи в `simplecheckout_shipping.twig` / `shipping_method.twig` рендерят карту ПВЗ и кнопку выбора.
2. **Экспорт заказа:** из карточки заказа админки (кнопки добавлены OCMOD в `order_info.twig`) или по cron (`export_order&key=<cron_key>`) → `POST /orders` в ApiShip → ApiShip сам создаёт отправление в Яндекс Доставке.
3. **Трек-статусы:** cron по `import_cron_url` тянет статусы из ApiShip и маппит в статусы OpenCart через `mapping_status`.

## Риски

1. **R-высокий. Расхождение токена.** Заказчик дал `y0__***` (OAuth Яндекса), а модулю нужен токен ApiShip из ЛК `apiship.ru`. Без ApiShip-токена модуль установится, но расчёт/экспорт работать не будут. **Требует подтверждения у заказчика:** либо он даст токен ApiShip (и тогда текущий путь верен), либо нужна прямая интеграция с `b2b.taxi.yandex.net` (другой модуль/разработка, задача 1.5 не покрывает).
2. **R-средний. Extension Installer может потребовать FTP.** OpenCart 3 при загрузке zip часто требует настроенный FTP (Settings → FTP) или корректный `DIR_STORAGE/marketplace/` с правами записи. Если упадёт — установка вручную (распаковать `upload/*` в корень сайта + `install.xml` → `system/apiship.ocmod.xml` + Refresh).
3. **R-низкий. Наложение кнопок apiship и правок tweak в карточке заказа.** Якоря разные, но визуально после Refresh надо проверить, что блок ApiShip и закомментированные tweak-ом функции не мешают друг другу.
4. **R-низкий. Наложенный платёж и Simple.** Поле `cash_on_delivery_payment_methods` корректно работает только при включённой загрузке доставок после оплат в Simple (установлен, задача 1.3). Без этого комиссия за наложенный платёж может считаться неточно.
5. **R-инфо. Возвраты в ПВЗ Планерная 47** в модуле как отдельное поле не настраиваются — это делается в ЛК ApiShip (правила возврата) и/или на стороне провайдера.

## Решения

- **D1.** Следовать проектному паттерну (задача 1.4): хранить модуль как zip + распакованный исходник `apiship-1.2_3.x.ocmod/` в корне репозитория, не раскладывая файлы по `admin/catalog/system`. Установка — через Extension Installer.
- **D2.** Не класть токены в репозиторий. Все секреты вводятся в админке и хранятся в `oc_setting`.
- **D3.** Перед установкой в живой админке — обновить модификаторы (Refresh) и очистить кэш; после — визуально проверить наличие кнопок ApiShip в карточке заказа и расчёта в чекауте.
