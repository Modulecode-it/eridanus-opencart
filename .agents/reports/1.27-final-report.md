## Сводка

`apiship_calculator()` кешировала **любой** ответ без `body.errors` на 1800 сек — включая пустой (`null`-body от сбоя curl/битого JSON) и урезанный (без тарифов yataxi). Хэш записи включает корзину → урезанный ответ «залипал» до 30 минут для всех покупателей с тем же товаром/адресом («пропадание» Яндекса из 1.25, живое подтверждение пустого кеша — в верификации 1.26). Фикс — трёхуровневое решение о кешировании:

| Ответ | Решение |
|---|---|
| Пустой: 0 тарифов в `deliveryToPoint` и `deliveryToDoor` (сюда же null-body) | не кешировать + лог `cache_empty_not_stored` |
| Асимметричный: тарифы только в одном из типов | TTL 120с + лог `cache_partial_ttl_120` |
| Полный по типам | TTL 300с (было 1800) |

Счёт тарифов зеркалит семантику catalog-модели (провайдер без `tariffs` = 0). Лог-маркеры пишутся через `toLog(..., error=true)` — всегда, без debug-режима.

## Известные пробелы

- Эвристика не ловит «симметричное урезание» (yataxi исчез из Point при живом Door) — для него окно режет только базовый TTL 300с; честного признака частичного ответа ApiShip не даёт.
- Регионы с честной асимметрией (Псков — только ПВЗ) получают TTL 120с — отображение не меняется, чуть больше запросов к ApiShip.
- Старые 30-мин записи кеша, созданные до деплоя, догорят сами ≤30 мин (опционально: удалить `system/storage/cache/apiship.*.cache`).
- При обновлении/переустановке модуля ApiShip вендор-файл затрёт 1.23+1.27 — сверять `system/library/apiship/apiship.php` после обновлений.
