**Дата:** 2026-09-07 (дополнения 2026-09-08)
**Статус:** завершена (все правки внесены и подтверждены на уровне настроек/API; визуальная витрин-проверка после инцидента восстановления — за пользователем, см. ниже)

## Сводка

Ответы на вопросы заказчика по странице `checkout/simplecheckout` + правки,
приводящие чекаут к стандартной логике по ТЗ (Яндекс через ApiShip: ПВЗ + курьер).

### Ответы

1. **«Выберите адрес», «, Санкт-Петербург,»** — поле Simple блока «Адрес доставки»
   (объединён с «Покупателем»); берёт значения из адресной книги залогиненного
   покупателя / адреса доставки в сессии и форматирует шаблоном
   `{firstname} {lastname}, {city}, {address_1}`. Строка неполная, потому что в
   адресе заполнен только город (имя/улица пустые). У аккаунтов lunkinmaks(±dev)
   и тестовых сохранённых адресов нет — значение из сессии чекаута.
2. **«Курьерская доставка» / «Доставка до ПВЗ»** — модуль Measoft (Е-Логистик),
   задача 1.4, ТЕСТОВЫЙ аккаунт (тарифы «170р./4.5 дней», ПВЗ «Mountain Blue» —
   данные тестовой среды). В актуальном ТЗ их нет; клиент с Е-Логистик не работает
   (spec 1.7). → **выключены**.
3. **ApiShip / 5Пост** — группа «ApiShip» = Яндекс.Доставка через ApiShip (боевая,
   из ТЗ). 5Пост подключён (задача 1.9), но тарифы в ApiShip ещё не активированы
   (калькулятор: `x5: tariffs=0` при живом yataxi) — методы появятся автоматически
   после активации тарифной сетки на стороне ApiShip.
4. **Оплата** — виден только Модульбанк («Оплата картой на сайте банка»).
   Установлены также: «Оплата при доставке» (включена, но геозона
   «Москва+Санкт-Петербург» — для адреса без зоны не показывается),
   «Банковский перевод», «Оплата наличными», «Наложка СДЭК», LIQPAY, PayPal ×3,
   «Бесплатный заказ» (все отключены). Включение — Расширения → Оплата → Изменить →
   Статус. НЮАНС: «Оплата при доставке» = наложный платёж; Яндекс.Доставка наложку
   без доработки не поддерживает (1.7) — включать только после решения курьерской схемы.
5. **Название «ApiShip»** → заменено на **«Доставка по России»** (подходит и для
   Яндекс.Доставки, и для будущего 5Пост в том же модуле).

## Проверка

- Гостевой чекаут открывается без редиректа на /login — проверено на витрине.
- Measoft ×2 = Отключено, ApiShip = Включено — проверено списком расширений.
- Новое название модуля перечитано из формы после сохранения.
- Сохранение набора полей — ответ API `{"success":true}` (HTTP 200).
- Локальные не-runtime проверки: чтение кода/языковых файлов/маршрутов; запрос к
  api.apiship.ru калькулятору (python).

## Известные пробелы

- **Витрина после восстановления настроек визуально не проверена** (транспорт
  browser-use в сессии деградировал). Была выявлена и устранена порча настроек
  Simple (неверный формат API-POST от 2026-09-07 → `[[]]`; восстановлено
  2026-09-08 через SPA-сохранение, верифицировано GET `/settings`:
  `guestCheckoutDisabled=false`, полный обязательный набор адресных полей,
  `hideForPaymentMethods` пуст). Проверка пользователем: чекаут гостем с товаром
  → блоки «Покупатель» (Город*/Адрес*), оплаты (Модульбанк + «Оплата при
  доставке»), доставки («Доставка по России»: Яндекс ПВЗ + курьер).
- Прод-репликация: настройки живут в БД dev. На проде повторить (Simple —
  экспортом/импортом настроек; Measoft ×2, ApiShip-название, COD-геозона —
  вручную в админке).

## Предложение по стилизации чекаута (не применено)

Цель — оформить страницу оформления заказа в стилистике сайта (тёмная шапка
`#37474F`, оранжевые акценты `#FF9800`, скруглённые карточки, Open Sans).
Вариант реализации — добавить в конец `catalog/view/theme/default/stylesheet/simple.css`
(файловая правка в гите; деплой — серверный шаг пользователя) блок:

```css

.simplecheckout-block {
    background: #fff;
    border: 1px solid #e8e8e8;
    border-radius: 10px;
    padding: 0 0 12px 0;
    margin-bottom: 18px;
    box-shadow: 0 2px 6px rgba(55, 71, 79, .06);
}
.simplecheckout-block .checkout-heading {
    background: #37474F;
    color: #fff;
    border-radius: 10px 10px 0 0;
    padding: 10px 16px;
    font-size: 15px;
    text-transform: none;
}
.simplecheckout-block .checkout-heading span { color: #fff; }
.simplecheckout-block-content { padding: 4px 16px 0 16px; }
.simplecheckout-block-content .form-control {
    border-radius: 6px;
    border-color: #cfd8dc;
    height: 38px;
}
.simplecheckout-block-content .form-control:focus {
    border-color: #FF9800;
    box-shadow: 0 0 0 3px rgba(255, 152, 0, .15);
}
#simplecheckout_button_confirm .btn,
#simplecheckout_button_confirm button {
    background: #FF9800;
    border: none;
    border-radius: 8px;
    color: #fff;
    font-weight: 600;
    padding: 12px 28px;
    text-transform: uppercase;
}

    background: #f57c00;
    color: #fff;
}
```

Альтернатива без правки файлов — поле кастомного CSS в настройках Simple
(«Интеграция с темой»), тогда деплой не нужен, но настройки переносятся
экспортом/импортом. Применить по согласованию с заказчиком.
