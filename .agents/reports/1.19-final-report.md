# Отчёт 1.19 — Инцидент переноса storage: закрыт

Дата закрытия: 2026-10-13. Полный ход расследования — `analysis/1.19`, `implementation/1.19`.

## Итог

**Инцидент storage (ошибка №1 заказчика) — закрыт 2026-10-12.** Перенос через окно
безопасности админки ничего не копировал (copy падал без прав), но безусловно
перезаписал `DIR_STORAGE` в конфигах на фантомный `/var/www/storage/` — warnings
на каждый запрос ломали заголовки (вход в админку — пустой 200, AJAX чекаута вис).
Фикс: sed в `config.php`/`admin/config.php` на `/var/www/html/system/storage/`
(Максим, на хосте). Верифицировано: warnings нет, админка работает, данные целы,
git-дерево сервера чисто. Правило в STACK: storage через админку не переносить.

**Хвост «Simple не рендерится» (жалобы №4/№5) — закрыт 2026-10-13.** Цепочка причин:
1. С 2026-10-05 02:23 сервер лицензий simpleopencart отвергал ранее выданный ключ
   (`simple wrong license4` в eri_error.log; данные/файлы/сеть у нас не менялись).
2. SimpleController уходил в unlicensed-фолбэк: рендерил штатный OpenCart-чекаут
   (Шаги 1–6) — отсюда «дублирование полей региона», «выберите адрес доставки»
   и «выбрать ПВЗ → главная» у заказчика. Заказы при этом оформлялись (подтвердил).
3. Лечение: заказчик запросил у разработчика свежий ключ для dev-домена (письмо
   из 1.20), ключ записан в `oc_setting.simple_license` UPDATE'ом (UI-поле активации
   было уже скрыто утренним вводом отозванного ключа) + сброс `cache.*`/`sess_*`.
