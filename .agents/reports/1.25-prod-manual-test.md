# Ручной тест-план на проде (eridanus.ru) — вопросы 1 и 2 из фидбека заказчика

**Задача:** 1.25-customer-feedback-round3
**Дата:** 2026-11-05
**Кто выполняет:** Максим (вручную, браузер)
**Важно:** все проверки — только на этапе выбора доставки/оплаты. Кнопку «Оформить заказ» в тестах НЕ нажимать (база боевая). Цены тарифов живые — могут гулять на десятки рублей, это норма.

## Подготовка (1 раз, ~2 мин)

1. Открыть любой товар в наличии, например:
   [3D конструктор Robotime Rumboks Цветочный магазин DG154](https://eridanus.ru/3d-derevyannyj-konstruktor-robotime-miniatyurnyj-dom-rumboks-cvetochnyj-magazin-dg154)
2. Нажать **«Купить»**.
3. Перейти в [корзину](https://eridanus.ru/cart) → **«Оформление заказа»**
   (прямая ссылка чекаута: https://eridanus.ru/index.php?route=checkout/simplecheckout ).
4. Заполнить «Адрес доставки»: Имя/Фамилия — любые, Страна — Российская Федерация,
   **Регион — «Санкт-Петербург»**.

## Задача 1. Город с ошибкой

### Тест 1.1 — опечатка в городе
1. В поле **Город** ввести с опечаткой: `Санкт-Петребург` (Индекс 190000, Адрес любой).
2. Подождать пересчёта блока «Способ доставки» (пара секунд).
3. **Ожидание:** методы на месте — «Самовывоз 5Post …», «Самовывоз Яндекс.Доставка …»,
   «Курьер Яндекс.Доставка …». ApiShip распознаёт опечатку сам.

### Тест 1.2 — несуществующий город
1. Сменить город на: `Ыфвапролдж` (регион тот же).
2. **Ожидание:** список урезается без сообщения об ошибке — остаются «Самовывоз 5Post» и
   «Самовывоз Яндекс.Доставка», **«Курьер Яндекс.Доставка» исчезает**. Красных ошибок нет.
3. Нажать «Оформить заказ» → **Ожидание:** заказ НЕ создаётся, видна ошибка
   «Пожалуйста, выберите ПВЗ!» (валидация задачи 1.23). Это подтверждает, что «в никуда» заказ не уйдёт.

### Тест 1.3 — пустой город (скриншот 1 заказчика)
1. Очистить поле «Город».
2. **Ожидание:** блок «Способ доставки» пуст — это норма (котировки не считаются без города).

## Задача 2. «Пропавшая» Яндекс-доставка

### Тест 2.1 — оплата картой (базовое состояние)
1. Город вернуть: `Санкт-Петербург`.
2. В «Способе оплаты» выбрать **«Оплата картой на сайте банка»**.
3. **Ожидание:** в «Способе доставки» видны все три метода:
   «Самовывоз 5Post … 363р.», «Самовывоз Яндекс.Доставка … 180р.», «Курьер Яндекс.Доставка … 338р.»
   (ориентиры по тесту 05.11; важно — присутствие Яндекса, не цены).

### Тест 2.2 — наложка скрывает курьера (механизм со скриншота заказчика)
1. Переключить оплату на **«Оплата при доставке»**.
2. **Ожидание:** «Курьер Яндекс.Доставка» исчезает, оба «Самовывоза» остаются.
3. Переключить оплату обратно на карту → курьер возвращается (пересчёт мгновенный).
   Если список не обновился — F5 и посмотреть ещё раз (кэш калькулятора до 30 мин, но у нала/карты он раздельный).

### Тест 2.3 — карта ПВЗ Яндекса живая
1. У «Самовывоз Яндекс.Доставка» нажать **«выбрать ПВЗ»**.
2. **Ожидание:** открывается карта с пунктами Яндекса в СПб (~7 точек по тесту 05.11).
3. Закрыть карту, ничего не выбирая (или выбрать и потом «сменить» — не критично).

### Тест 2.4 — сценарий заказчика (своей записью, наложка)
1. В чекауте нажать **«Я зарегистрирован»**, войти под своей записью.
2. Оплата — «Оплата при доставке», корзина — тот же «боевой» состав, что был у заказчика.
3. **Ожидание:** остаётся «Самовывоз 5Post» с постаматом из тестового заказа (или без него) и
   **без Яндекса** — это и есть скриншот заказчика: наложка убрала курьера, а для тяжёлой/многопозиционной
   корзины ApiShip не дал Яндекс-тарифов вовсе.
4. Не меняя корзину, переключить оплату на карту:
   - если Яндекс появился — виновата была только наложка;
   - если не появился — корзина не проходит лимиты Яндекса (вес/габариты) → уменьшить
     количество до 1–2 шт и проверить ещё раз — Яндекс появится.
5. Для чистоты эксперимента можно повторить наоборот: количество ×10 при оплате картой →
   **Ожидание:** исчезает уже «Самовывоз 5Post», Яндекс остаётся (лимиты x5 строже).

## Что считать проблемой

- При оплате картой, городе без опечатки и лёгкой корзине (1–2 товара) нет ни ПВЗ, ни курьера Яндекса.
- Карта ПВЗ Яндекса не открывается / пустая.
- Заказ создаётся без выбранного ПВЗ или без адреса при курьере.
- Пустой блок доставки при корректно заполненном городе (СПб) и лёгкой корзине.

Во всех остальных случаях (урезанный список при наложке/тяжёлой корзине/мусорном городе) —
штатное поведение ApiShip, зафиксировано в analysis 1.25.
