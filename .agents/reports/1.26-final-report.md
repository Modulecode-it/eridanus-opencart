## Сводка

Симптом (dev, гость): после ввода региона и города клик «выбрать ПВЗ» не открывает карту, в консоли `Uncaught ReferenceError: ApishipMap is not defined` и шум «(Yandex Maps JS API): Invalid API key» от `ns=cdekymap`.

**Причина:** `catalog/view/javascript/apiship.js` объявляет виджет как `class ApishipMap {...}`. Когда apiship-котировки впервые появляются через AJAX-перегрузку блока Simple (типичный путь гостя: страница чекаута открыта без города → город введён → блок перегрузился), jQuery 2.1.1 исполняет `<script src=apiship.js>` из вставленного HTML не как браузерный скрипт, а через `$.ajax({dataType:"script"})` → `globalEval` → **indirect eval**, в котором декларации `class` не выживают после завершения eval. Инлайн-скрипт блока (function-декларации: `apiship_open` и др.) при этом выживает — отсюда точная картина ошибки: запрос точек проходит (`get_points` → `no_error`, 421 КБ), а на `new ApishipMap` — ReferenceError. Если котировки были уже при серверном рендере страницы, файл исполняется настоящим `<script>`-тегом и класс живёт — поэтому прежние проверки карты проходили.

«Invalid API key» (`ns=cdekymap`) — отдельный шум виджета СДЭК (`catalog/controller/event/cdekshipping.php` подключает api-maps.yandex.ru без ключа), карту ApiShip не блокирует.

**Фикс:** `var ApishipMap = class ApishipMap {...};` (var-присваивание кладёт класс на `window` и переживает indirect eval; при обычной загрузке поведение то же) — в `catalog/view/javascript/apiship.js` и синхронно в копии пакета `apiship-1.2_3.x.ocmod/upload/...`.
