## R1.2 — Баг «курьер пропадает при переключении оплаты» (анализ кода)

### Механизм «нал = только ПВЗ» (из 1.14)

`shipping_apiship_cash_on_delivery_payment_methods` = `['cod']`. В модели `catalog/model/extension/shipping/apiship.php` (`get_quote_list`, вызывается из `getQuote`) код выбранной оплаты сравнивается со списком; при совпадении котировка ApiShip считается с `codCost` — а API Яндекса при `codCost` возвращает только ПВЗ-тарифы (курьер/дверь исчезают). Кэш калькулятора тут НЕ виноват: ключ `md5(...$cash_on_delivery...)` в `system/library/apiship/apiship.php:345` различает оплату нал/карта.

### Корневая причина — лаг сессии на один перерасчёт

В Simple-чекауте порядок рендера блоков задаёт `SimpleCheckout::isPaymentBeforeShipping()` (`system/library/simple/simplecheckout.php:170`, настройка `paymentBeforeShipping`; в бэкапе настроек 1.13 ключа нет → false → **доставка рендерится раньше оплаты**; главный контроллер `catalog/controller/checkout/simplecheckout.php:109-115`).

Радио оплаты имеет `data-onchange="reloadAll"` → главный контроллер POST-ом всей формы перерендеривает все блоки в порядке: shipping → payment. Блок доставки при рендере читает `$this->session->data['payment_method']['code']` (apiship.php, 3 места), а блок оплаты записывает туда свежее значение только ПОСЛЕ доставки. Итог — котировки всегда считаются по способу оплаты из **предыдущего** состояния:

| Действие | Котировки при рендере | Видно пользователю |
|---|---|---|
| карта выбрана | по карте | курьер есть ✓ |
| переключение на «при доставке» | ещё по карте | курьер остаётся (нал с курьером — тоже баг) |
| переключение обратно на карту | ещё по налу (codCost) | **курьера нет** — репорт заказчика ✓ |

### Почему не настройка `paymentBeforeShipping`

Простое переключение на «оплата раньше доставки» чинило бы лаг без деплоя (настройка в БД), НО: Simple зашифрован ionCube (`system/library/simple/php/simple_system_*.php`), настройка нигде не exposed в админке, её место в JSON настроек неизвестно, а смена режима меняет семантику привязок `forMethods` (library lines 672/744/751/836). Привязок в настройках нет, но инжект неизвестного ключа в зашифрованное расширение — непредсказуем. Отклонено.

### Принятый фикс

`catalog/model/extension/shipping/apiship.php`: новый приватный `get_payment_method_code()` — при наличии `$_POST['payment_method']` (AJAX-перезагрузка Simple шлёт всю форму, включая только что выбранный radio) берём оплату из POST, иначе fallback на сессию. Заменены 3 места чтения: `get_quote_list` (рендер блока доставки), `get_points_array` (данные карты ПВЗ), `set_point` (выбор точки). Тени OCMOD у модели нет — правится только оригинальный файл, деплой штатным `git pull`.

Безопасность: в админ-контекстах POST `payment_method` содержит title («Оплата при доставке»), а не код — `in_array(..., ['cod'])` даёт false, как и прежняя пустая сессия → поведение не меняется. При блочной перезагрузке только блока доставки POST не содержит оплату → fallback на сессию (как сейчас).

### Проверка (план)

- До деплоя: репро на dev текущим кодом — переключить карту→нал→карта, зафиксировать, что курьер пропадает именно на шаге «обратно».
- После `git pull` (шаг Максима): тот же сценарий — курьер исчезает сразу при нале и возвращается при карте.
