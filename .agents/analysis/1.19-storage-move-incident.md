# Анализ 1.19 — Диагностика последствий переноса storage (dev, 2026-10-12)

Метод: браузер (vitрина + админка, сессия AI) + чтение кода. PHP/БД локально не запускались.

## Воспроизведённые факты

1. **Warnings на каждой странице админки** — в точности как у заказчика:
   `Warning: fopen(/var/www/storage/logs/openbay.log): failed to open stream: No such file or directory in /var/www/html/system/library/log.php on line 22`
   и то же для `eri_error.log`. Каталог `/var/www/storage/logs` не существует. Оба лога
   инициализируются при каждом запросе админки — предупреждения летят в вывод до отдачи
   страницы (в т.ч. до `header()`).

2. **Вход в админку сломан механикой «headers already sent»**: POST
   `/admin/index.php?route=common/login` с верными кредами `ai_agent` возвращает
   **HTTP 200 с телом 344 байта — только два warnings, без HTML и без `Location`**.
   Редирект на дашборд ставится через `header()` после вывода → не срабатывает;
   страница остаётся пустой. Переход на дашборд вручную → «Неправильная токен-сессия.
   Авторизуйтесь снова». То есть админка недоступна всем, включая заказчика
   (их «работает» из письма касалось входа до переноса storage).

3. **Витрина в основном жива** — значит, перенос скопировал большую часть storage:
   - корзина/сессии работают между страницами → `/var/www/storage/session` существует;
   - модалка «Уведомить о наличии» на карточке Беретты открывается (twig-тень из
     `modification`) → `/var/www/storage/modification` читается;
   - страницы рендерятся → `vendor` на новом пути работает.

4. **SimpleCheckout не рендерится нигде**:
   - `index.php?route=checkout/simplecheckout` → 301 на `/checkout` (блок «Redirect 301»
     патченного `catalog/controller/startup/seo_url.php`: роут есть в `oc_seo_url`);
   - `/checkout` рендерит **штатный** чекаут (Шаги 1–6, `collapse-checkout-option`),
     маркеры Simple (`simplecheckout_customer`, `simplecheckout_block`, simple.js) отсутствуют;
   - следовательно, у заказчика на этой неделе был именно штатный чекаут — отсюда их
     пункт 4 (регион спрашивается «в корзине»/в форме, потом те же поля повторяются,
     отдельный шаг «выберите адрес доставки») и, вероятно, пункт 5 (ПВЗ).
   - механизм отключения Simple не установлен (нужна админка/БД): кандидаты — статус
     модуля, повреждение `simple_settings` (прецедент 1.17), флаг `simple_unlicensed`
     (см. `system/library/simple/rewrite.php`). 2026-09-30 Simple работал (1.16/1.17).

5. **Штатный чекаут гостем падает на сохранении адреса**: форма Шага 2 (Имя/Фамилия/
   E-Mail/Телефон + Адрес/Город/Индекс/Страна/Регион-select) рендерится; после
   «Продолжить» кнопка зависает в «Загрузка...», способы доставки не загружаются —
   AJAX-ответ невалиден (та же причина: warnings в теле + сломанные редиректы).

6. **Ссылка «выбрать ПВЗ» существует в обоих шаблонах** (тени ApiShip):
   `system/storage/modification/catalog/view/theme/default/template/checkout/shipping_method.twig`
   и `.../simplecheckout_shipping.twig`: `<a class="..." href="#" onclick="{{ quote.apiship_link }}">`
   (вызов `apiship_open(code)` из 1.16). В штатном чекауте шаг доставки не открылся —
   клик не проверен; «выкидывает на главную» у заказчика правдоподобно связано с
   аварийным режимом (сломанные редиректы/JS-обработчик), финальная проверка — после
   восстановления Simple.

7. **Курьер Яндекс.Доставки оформляется** (подтверждение заказчика) — заказ создаётся
   в БД до финального редиректа, поэтому сбой заголовков не мешает самому заказу.

8. **Побочное**: у товара «Беретта» в админке кем-то изменено наличие («Наличие: В наличии»
   при quantity=0 — кнопка уведомления при этом по-прежнему срабатывает по количеству).
   К инциденту отношения не имеет, при приёмке вернуть товар в состояние «Нет в наличии»
   для тестов кнопки.

## Состояние git/файлов сервера

- `config.php`, `admin/config.php` — gitignored: их правка переносом конфликта git не создаёт.
- Перенос переименовал `system/storage` → `/var/www/storage`, поэтому tracked-файлы
  `system/storage/modification/**` (тени ApiShip 1.14, availpro 1.18, loader/action и др.)
  в рабочем дереве сервера сейчас «удалены»: `git status` грязный, `git pull`, меняющий
  тени, не пройдёт. Откат переноса возвращает консистентность рабочему дереву.
- `/var/www/storage` лежит вне worktree (bind mount репо) → содержимое не переживает
  пересоздание контейнера — ещё одна причина отката.

## Вывод

Единая корневая причина симптомов заказчика №1, №4 (частично), №5, №6 — незавершённый
перенос storage: warnings на каждый запрос ломают заголовки (вход в админку, AJAX
чекаута, редиректы), отсутствующий logs-каталог отключил журналирование ошибок.
Отсутствие Simple — сопутствующий сбой той же недели (проверить после восстановления
входа). Лечение: откат переноса (см. implementation log), затем верификация чекаута
и ПВЗ, затем разбор Simple.
