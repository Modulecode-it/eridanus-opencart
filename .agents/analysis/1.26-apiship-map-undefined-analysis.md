## Механизм (доказательство по коду репо)

1. **Кто вставляет блок.** `catalog/view/javascript/simplecheckout.js:1490` — `$(container).html(newData)` / `:1492` `replaceWith(newData)`; в `simplecheckout_shipping.twig` (тень modification, строки 13–17) выводится `{{ shipping_method['script'] }}` — инлайн-скрипт + `<script src="catalog/view/javascript/apiship.js?v=...">` прямо в HTML блока.
2. **Как jQuery исполняет скрипты из вставленного HTML** (jquery-2.1.1.min.js из репо):
   - инлайн: `globalEval(text)` — из minified: `globalEval:function(a){var b,c=eval;...c(a)}` — **indirect eval** (вызов через переменную `c`, не literal `eval(...)`);
   - внешний: `h.src?n._evalUrl(h.src):...`, `_evalUrl=function(a){return n.ajax({url:a,type:"GET",dataType:"script",async:!1,...})}` — синхронный ajax, ответ исполняется тем же `globalEval`.
3. **Семантика indirect eval** (ES-спека): `var`/function-декларации попадают на global object и выживают; `let/const/class` создаются в **новом декларативном окружении данного вызова eval** и удаляются по его завершении.
4. **Следствие для нашего кода:**
   - инлайн-скрипт модели `apiship.php` (строки 731–856: `function apiship_open`, `function get_yandex_api_key`, ...) — function-декларации → выжили на `window` → клик по «выбрать ПВЗ» сработал, `get_points` ушёл;
   - `catalog/view/javascript/apiship.js:1` — `class ApishipMap {...}` → исполнен через `_evalUrl`→`globalEval` → **биндинг класса исчез сразу после eval** → `new ApishipMap` → ReferenceError.
5. **Почему ошибка видна только после ввода региона/города.** При первичном рендере страницы без города apiship-котировок нет → тег `apiship.js` отсутствует → класс не определён. Котировки появляются первой AJAX-перегрузкой блока (введён город) → первый запуск файла — именно через eval-путь. Если котировки уже были при серверном рендере (в сессии есть город), тег исполняется браузером как настоящий `<script>` → класс попадает в global lexical environment и живёт до закрытия страницы; дальнейшие AJAX-перегрузки его не ломают (повторный eval создаёт временный биндинг, глобальный остаётся). Этим объясняется, почему прежние проверки (1.14/1.19/1.21 — карта «работает») проходили: в тех сессиях город уже был, либо была полная перезагрузка страницы.

## Сопутствующая ошибка «Invalid API key» (ns=cdekymap) — шум, не причина

`catalog/controller/event/cdekshipping.php:5` подключает на странице `//api-maps.yandex.ru/2.1/?lang=ru_RU&ns=cdekymap` (виджет СДЭК, `sdek.js`) **без apikey** — Яндекс Maps JS API 2.1 без ключа отвечает «Invalid API key» и не инициализируется. Это отдельный загрузчик со своим namespace (`cdekymap`), не мешает виджету ApiShip (свой ключ + свой ns по умолчанию). Живёт давно, ошибка в консоли видна на каждом чекауте. Кандидат на чистку: СДЭК-доставка не используется (агрегатор ApiShip), событие можно отключить (отдельная операция, требует бекапа — не в этой задаче).

## Риски и решения

- **Риск:** повторное исполнение файла (серверный рендер + AJAX) — безопасно: `var`-переопределение идентично, временный class-биндинг в eval не конфликтует с глобальным.
- **Риск:** обновление модуля ApiShip перезапишет фикс — копия в пакете синхронизирована; при обновлении модуля сверять этот файл (заметка в implementation log).
- **На проде** тот же механизм (ApiShipTemplatesFix вернул те же шаблоны): после деплоя фикса проверить идентичный сценарий.
