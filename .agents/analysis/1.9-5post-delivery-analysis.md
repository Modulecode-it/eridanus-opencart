## Что за сервис

«Доставка через Пятёрочку (постаматы и кассы)» = **5Пост (FivePost)** —
логистический сервис X5 Group (бренд «Пятёрочка»). Выдача заказов:
постаматы и кассы магазинов «Пятёрочка». Сайт `fivepost.ru`, подключение
юрлиц — `fivepost.ru/become-partner/`. Именно формулировка заказчика
«постаматы и кассы» указывает на 5Пост (получение на кассе — их фирменная
опция). Мобильный трекер заказов — «5 POST» (ru.x5.omni), что выдаёт
внутреннее имя платформы Omni.

## Маршруты подключения

### Маршрут A (рекомендуемый): провайдер «5Пост» в ApiShip

- Уже есть боевой модуль ApiShip 1.2 (задачи 1.5–1.8): токен, экспорт
  заказов, маппинг статусов, cron — всё работает с Яндексом.
- Партнёрство ApiShip и 5Пост (новость apiship.ru): магазины,
  интегрированные с ApiShip, подключают 5Пост ускоренно — заявлялось
  сокращение сроков «с нескольких недель до одного дня».
- Ожидаемые шаги = повторение 1.7 для нового провайдера: подключить СД
  в ЛК ApiShip (Службы доставки → 5Пост; поля формы — вероятно, ИНН +
  ключ/токен, по аналогии с формой Яндекса), включить провайдера в
  настройках модуля, сопоставить статусы, приёмочный тест.
- Кодовых изменений не планируется: провайдеры подтягиваются в модуль из
  `api.apiship.ru` (AJAX-вкладка «Провайдеры»), ПВЗ — единым справочником.

### Маршрут B (резерв): прямая интеграция

- Прямой API 5Пост (шлюз X5 Omni на Apigee):
  - прод: `https://api-omni.x5.ru`, тест: `https://api-preprod-omni.x5.ru`;
  - авторизация: **consumer key** (api-key) →
    `POST /jwt-generate-claims/rs256/1?apikey=<key>`
    (form_params: `subject=OpenAPI`, `audience=A122019!`) → ответ `{"jwt": ...}`,
    токен живёт 1 час; далее во всех запросах
    `Authorization: Bearer <jwt>`. В payload JWT — `partnerId`, `apikey`.
  - «consumer key» — штатный термин Apigee; именно так назван ключ,
    выданный заказчиком (подтверждает, что ключ — от шлюза X5/5Пост).
- Готовый модуль для OpenCart от iPol (официальный): `ipol.ru/spravka/5post_opencart` —
  отправка заявок и мониторинг статусов; потребует настройки параллельно
  с ApiShip.
- Минусы маршрута B: второй контур выгрузки/статусов рядом с ApiShip,
  дублирование логики в чекауте/Simple, отдельная поддержка.

## Куда попадает ключ

- `.secrets/5post.md` — заготовка создана 2026-09-01, значение
  `REPLACE-ME-5POST-CONSUMER-KEY` до передачи заказчиком.
- При маршруте A ключ, вероятно, вводится в ЛК `apiship.ru` при подключении
  СД 5Пост (аналог YandexOAuthToken в 1.7); при маршруте B — в настройках
  прямого модуля/API-клиента.

## Риски / Открытые вопросы

- Статус договора заказчика с 5Пост не подтверждён (ключ выдан — вероятно,
  договор есть; уточнить у заказчика).
- Есть ли `consumer secret` (в Apigee выдаются парой) и `partnerId` —
  запросить у заказчика при необходимости.
- Способ сдачи груза у 5Пост: своя точка приёма/склад в СПб (точка Яндекса
  1043536 «Планерная 47» не относится к 5Пост) — выяснить в ЛК после
  подключения; от этого зависит pointInId или курьерский забор.
- Лимиты постаматов (габариты/вес) и поддержка наложенного платежа 5Пост —
  влияют на чекаут и на R6-тест (наложка у Яндекса уже показала себя
  ограничением в 1.7).
- Статусная модель 5Пост в ApiShip — маппинг настраивается после
  подключения (фактические статусы увидим в ЛК).

## Дополнение 2026-09-01 (после боевого подключения)

Подключение выполнено (connection id=39490, склад создан, провайдер
включён в модуле — см. implementation log). Ключевой факт диагностики:
**калькулятор ApiShip возвращает `providerKey=x5` с пустым `tariffs[]`** —
и в модуле, и в штатном калькуляторе ЛК; ПВЗ «Пятёрочка» в справочнике
`lists/points?providerKey=x5` при этом уже есть. Вывод: тарифная сетка
5Пост привязывается к подключению с задержкой (активация на стороне
ApiShip/5Пост, заявленный срок подключения — до 1 дня). Настройки модуля
корректны и дополнительного кода не требуется: при появлении тарифов
методы `point_x5_*` возникнут в чекауте автоматически (калькулятор
вызывается без `providerKeys`, фильтрация по включённым pickup_types).

Быстрая проверка появления тарифов (python, UTF-8 — не curl из Git Bash
с кириллицей в `-d`):

```python
import json, re, urllib.request
token = re.search(r'ApiToken:\s*(\S+)', open('.secrets/apiship-lk.md', encoding='utf-8').read()).group(1)
body = json.dumps({
  "from": {"countryCode": "RU", "addressString": "Санкт-Петербург ,  Санкт-Петербург,  Планерная, д.47"},
  "to":   {"countryCode": "RU", "addressString": "Санкт-Петербург ,  Санкт-Петербург,  Невский пр-т, 28"},
  "places": [{"height": 10, "length": 27, "width": 21, "weight": 500}],
  "assessedCost": 1000, "includeFees": False,
}).encode()
req = urllib.request.Request("https://api.apiship.ru/v1/calculator", data=body,
  headers={"Authorization": token, "Content-Type": "application/json", "Accept": "application/json"})
d = json.load(urllib.request.urlopen(req, timeout=20))
print([(k, x["providerKey"], len(x.get("tariffs") or [])) for k in ("deliveryToPoint", "deliveryToDoor") for x in (d.get(k) or [])])
# x5=0 → ещё не активны; x5>0 → можно проводить R5/R6
```
