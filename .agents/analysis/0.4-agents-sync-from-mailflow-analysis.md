## Сверка окружения

- Наш remote: `git@github.com:Modulecode-it/eridanus-opencart.git` (**SSH**), ветка `main`. Remote донора — HTTPS, поэтому у донора схема HTTPS + PAT работает через `origin`; нам URL HTTPS надо указывать в командах явно.
- Аккаунт GitHub один и тот же (`Modulecode-it`) — PAT донора валиден для нашего репо, пользователь подтвердил его использование.
- Локальный PHP-бинарник отсутствует (`php: command not found`) — в скилле `no-local-testing` формулировка про `php -l` должна быть условной («если PHP есть локально»).
- Концовки строк: донорский `git-sync/SKILL.md` — CRLF, `no-local-testing/SKILL.md` — LF. Наши файлы — CRLF; все новые файлы конвертируются в CRLF после записи.

## Поток Данных

Не применим (задача документационно-инфраструктурная: файлы `.agents/` и корневой `AGENTS.md`; код проекта не меняется).

## Риски

1. **Утечка Laravel-терминов** из формулировок донора (artisan/composer/Docker/Blade и т.п.) в переносимые файлы. Митигация: стоп-лист + финальный `grep`.
2. **Утечка секрета**: в SKILL.md донора зашит реальный PAT. Переносится ТОЛЬКО по явному подтверждению пользователя (получено) и только в `git-sync/SKILL.md`. Это осознанное исключение из правила «не хранить секреты в `.agents/`», как в доноре.
3. **Конфликт схемы remote**: наш remote SSH, скилл построен на HTTPS+PAT. Митигация: в командах скилла указывается явный HTTPS-URL репо вместо `origin`.
4. **Дублирование уже существующего правила** v1.0.1 (запрет локального HTTP-тестирования). Митигация: `no-local-testing` ссылается на правило, а не дублирует его.

## Решения

1. Универсальные файлы (`CORE.md`, `RULES.md`, `ONBOARDING.md`, `prompts/*`) не трогать — идентичны донору. `CHECKLISTS.md` не трогать — наш новее.
2. `README.md` дополнить формулировками донора; заодно исправляется заголовок `.agent` → `.agents` (недосмотр задачи 0.3).
3. `git-sync` — структура донора, PAT донора (подтверждён пользователем), команды адаптированы под явный HTTPS-URL нашего репо и ветку `main`.
4. `no-local-testing` — переписать под OpenCart: без artisan/composer/sail/pest/Docker; суть — сайт на сервере, локальной среды запуска нет; отсылка к правилу v1.0.1 в `STACK.md`; список допустимых локальных статических проверок.
5. Корневой `AGENTS.md` — 3 новые секции после «graphify», стиль существующего документа сохраняется.

## Архитектурные Решения

- Без ADR: изменения не выходят за рамки servicing системы памяти (задача 0.x), архитектура памяти не меняется.
