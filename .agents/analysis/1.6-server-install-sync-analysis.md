**Статус:** завершён (анализ)

## Текущее Поведение

После установки модулей через админку (Extension Installer) на сервере
`/var/www/eridanus.dev.modulecode.ru/opencart` (ветка `main`, HEAD `29b36f9`):

- 21 tracked-файл показывался как modified;
- 16 файлов ApiShip по рабочим путям — untracked;
- при этом сервер **отставал от origin/main**: его `origin/main` указывал на
  `29b36f9` (коммит до мержа задачи 1.5), fetch не выполнялся — пакета
  `apiship-1.2_3.x.ocmod/` на диске сервера не было.

## Сверка ApiShip: сервер ↔ пакет в git

- 16 текстовых файлов: md5 серверных **полностью совпали** с `git show HEAD:apiship-1.2_3.x.ocmod/upload/<path>`.
- 6 картинок (`admin/view/image/shipping/apiship*.{png,gif}`, `catalog/view/theme/default/image/shipping/apiship_*.{png,gif}`): md5 серверных совпали с файлами пакета на диске.
- `system/library/apiship/` содержит только `apiship.php` (35115 байт), runtime-файлов нет.

Вывод: перенос файлов с сервера не требуется — рабочие пути восстанавливаются
локально из пакета, байт-в-байт равные серверным.

## Дыра .gitignore: правило `image/`

Правило `image/` (задуманное для корневого каталога картинок товаров, 29 ГБ)
матчило **любую** директорию `image/` на любой глубине. Последствия:

1. 6 картинок ApiShip не попали в git даже внутри пакета `apiship-1.2_3.x.ocmod/` при задаче 1.5.
2. 6 картинок Measoft не попали в пакет `measoft_oc3.ocmod/` при задаче 1.4 и в рабочие пути.
3. Вся статика ассетов (`admin/view/image/**`: payment/cdek/facebook/d_seo_module/…;
   `catalog/view/theme/default/image/**`: eway/paypal/default; `catalog/view/image/**`:
   ассеты Simple; `admin/view/javascript/jquery/flot/examples/image/`) — не версионировалась,
   хотя присутствует в локальном рабочем дереве (полный клон с сервера).

Фикс: `image/` → `/image/` (игнорировать только корневую). Трекаемых файлов внутри
вложенных `image/` до фикса было 0, конфликтов нет.

## Поток Данных

Deploy-модель проекта: сервер = git clone, изменения идут локальный main → GitHub →
`git pull` на сервере. Установка модуля через админку создаёт файлы в обход git —
их нужно осознанно переносить в репо (по образцу задач 1.4/1.5: пакет + рабочие пути).

## Риски

- **Затёртые патчи Measoft**: пока на сервере не выполнен `git checkout -- <4 файла>`,
  расчёт доставки Measoft работает без конвертации кг и без `paytype` (регрессия с 1.4).
- **Untracked-блокировка merge**: после добавления рабочих путей в main на сервере
  `git pull` откажется перезаписывать untracked-файлы — обязательно
  `git stash push -u` до merge.
- **Дрейф статики**: локальный baseline вложенных `image/` снят при первоначальном
  клоне; если на сервере какие-то ассеты менялись после клона, после sync они
  останутся в stash — сверить при выполнении серверных шагов.

## Решения

1. Серверские версии 4 патчённых файлов Measoft и mode-change шум — не коммитить.
2. Рабочие пути ApiShip (22 файла) разложить из пакета в git (blob == серверные md5).
3. `.gitignore`: `image/` → `/image/`; добавить всю вскрывшуюся статику как baseline.
4. Сервер обновлять по схеме: `git checkout -- .` → `git stash push -u` → `git fetch` + `git merge --ff-only origin/main` → контроль `git status` → `git stash drop`.
