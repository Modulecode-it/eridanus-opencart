## Цель

Разобрать вопросы заказчика по странице оформления заказа
(`checkout/simplecheckout`) и привести чекаут к стандартной логике интернет-магазина
по действующему ТЗ (доставка по РФ: ПВЗ + курьер; сдача/возвраты через ПВЗ Планерная 47 — задачи 1.7/1.8):

1. Пояснить поле «Выберите адрес» в блоке «Покупатель»: откуда берётся адрес, почему неполный; исправить.
2. Пояснить методы «Курьерская доставка» и «Доставка до ПВЗ» (источник, соответствие ТЗ).
3. Пояснить отсутствие 5Пост в методах ApiShip (задача 1.9).
4. Пояснить единственный способ оплаты «Оплата картой на сайте банка» (Модульбанк), наличие и включаемость других.
5. Заменить название группы «ApiShip» на покупательское.
6. Оценить и предложить улучшение внешнего вида чекаута в стилистике сайта.

## Область

- Настройки модулей в БД через админку dev-сайта (Simple, Measoft ×2, ApiShip, COD) — код не меняется.
- Витрина: верификация чекаута гостем.

## Требования

- R1. Гостевой заказ разрешён (стандартная логика): снять «Требовать авторизацию для оформления заказа» в Simple.
- R2. Тестовые методы Measoft (Е-Логистик, тестовый аккаунт) выключены из чекаута.
- R3. Название группы доставки ApiShip заменено на покупательское («Доставка по России»).
- R4. В блоке адреса доступны поля Города и Адреса для гостя (иначе доставка не считается).
- R5. Ответы на вопросы 1–4 переданы заказчику, предложения по стилизации — отдельным разделом.

## Ограничения

- Работы через браузер на dev-сайте (правила 0.5); креды `.secrets/dev-admin.md`.
- Изменения — только настройки в БД; код репозитория не трогаем.
- База — копия боевой: реальные заказы/клиенты не трогать.

## Критерии приёмки

- A1. Гость может открыть чекаут без редиректа на /login и ввести город/адрес.
- A2. В чекауте нет методов Measoft («Курьерская доставка … 170р.», «Доставка до ПВЗ … Mountain Blue»).
- A3. Группа доставки называется «Доставка по России» (Яндекс: ПВЗ + курьер).
- A4. Документы 1.10 оформлены, INDEX обновлён.
