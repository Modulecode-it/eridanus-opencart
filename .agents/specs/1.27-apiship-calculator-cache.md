# Задача 1.27 — Кеш калькулятора ApiShip: не фиксировать пустые/урезанные ответы

**Задача:** 1.27-apiship-calculator-cache
**Дата:** 2026-11-18
**Статус:** в работе

## Цель

Устранить «залипание» урезанного/пустого списка доставки до 30 минут: транзиентный сбой калькулятора ApiShip (пустой ответ, ответ без тарифов Яндекса и т.п.) фиксируется общим файловым кешом на 1800 сек и показывается всем покупателям с той же корзиной/адресом. Диагноз поставлен в 1.25 (сессия-3, HAR заказчика) и подтверждён живым кейсом в 1.26 (пустой ответ «Единорог×1+СПб+карта» закеширован на обоих сайтах).

## Область

- `system/library/apiship/apiship.php` — `apiship_calculator()` (кеш `apiship_calculator`, строки ~386/482) и `sharedCacheGet/Set`.
- Копия пакета `apiship-1.2_3.x.ocmod/upload/system/library/apiship/apiship.php` — **не трогаем**: это вендор-оригинал, правки eridanus perf (1.23) в него не синхронизировались (прецедент 1.23).

## Требования

1. Пустой ответ калькулятора (нет тарифов ни в `deliveryToPoint`, ни в `deliveryToDoor`; сюда же `body = null` от curl-сбоя/битого JSON) — **не кешировать вовсе**; лог-маркер с `x-tracing-id`.
2. Асимметричный ответ (тарифы есть только в одном из типов доставки) — короткий TTL **120 сек** вместо базового; лог-маркер (может быть как честным покрытием региона — Псков, так и урезанным ответом агрегатора).
3. Базовый TTL полного ответа: 1800 → **300 сек** (сокращает окно необнаружимых урезаний — главный кейс HAR 1.25: yataxi исчез из Point при живом Door, симметрию не нарушает).
4. Поведение возврата из `apiship_calculator()` для вызывающих не меняется (форма `$data` та же); правка только решения о кешировании.
5. Лог-маркеры пишутся через существующий `toLog(..., error=true)` — попадают в лог всегда, без debug-режима.

## Ограничения

- Минимальная правка в стиле окружающего кода (tabs, старый синтаксис), без изменения логики расчёта/запроса.
- Эвристика «урезанности» честного признака не имеет (ApiShip не помечает частичные ответы) — ложные срабатывания на регионах с реальным отсутствием одного из типов доставки приемлемы (для них просто TTL 120с).
- Проверка только статическая (PHP-бинарника локально нет); runtime-верификация — на dev после деплоя.

## Критерии Приёмки

- Статический разбор: пустой/`null`-body не доходит до `sharedCacheSet`; асимметричный — TTL 120; полный — TTL 300; вызовы `$this->apiship->apiship_calculator()` в catalog-модели не требуют правок.
- На dev после деплоя: обычный сценарий котировок (СПб, полный ответ) работает; в логе при сбое ApiShip появляются маркеры; урезанное/пустое окно ≤ 120 сек / отсутствие кеша.
- `git diff` — только задуманный блок в `system/library/apiship/apiship.php`.
