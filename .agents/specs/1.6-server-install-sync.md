# Спецификация: Синхронизация серверных артефактов установки модулей с git

**Задача:** 1.6-server-install-sync
**Дата:** 2026-08-18
**Статус:** в работе

## Цель

Забрать в git изменения, возникшие на сервере после установки модулей через админку
(Extension Installer), и привести сервер к чистому `git status` без потери рабочих
данных и кастомных патчей проекта.

## Контекст (исходное состояние сервера)

Сервер `/var/www/eridanus.dev.modulecode.ru/opencart`, ветка `main`, up to date с `origin/main`:

- **Modified (21 tracked-файл):** 20 файлов Measoft (задача 1.4, в репо 4 из них несут
  кастомные патчи `getWeight()`/`paytype`) + `admin/view/stylesheet/bootstrap.css` (ядро админки).
- **Untracked:** рабочие файлы ApiShip 1.2 (задача 1.5: в main хранится только пакет
  `apiship-1.2_3.x.ocmod/`, по рабочим путям файлы не раскладывались) + select2/i18n в
  `admin/view/javascript/`.

## Область

1. Диагностика природы изменений на сервере:
   - mode change (веб-процесс писал файлы от другого владельца);
   - CRLF↔LF (installer перезаписал файлы из zip);
   - реальная перезапись контентом пакета (риск затирания 4 патченных файлов Measoft);
   - реальные новые изменения (в т.ч. `bootstrap.css`).
2. Сверка untracked apiship-файлов с пакетом `apiship-1.2_3.x.ocmod/upload/**` в main.
3. Версионирование рабочих путей ApiShip в main по образцу задачи 1.4 (measoft).
4. Восстановление/сохранение кастомных патчей Measoft, если installer их затёр.
5. Возврат сервера к чистому `git status` через stash + pull (без `git clean -fd`).

## Требования

- Серверные изменения НЕ терять до их анализа (сначала snapshot: diff-патч + tar untracked, или stash с сохранением).
- Не коммитить шум (mode changes, CRLF) — нормализовать как в 1.4 (LF в репо).
- Секреты (токены ApiShip/Яндекс) в git не попадают; настройки живут в БД (`oc_setting`).
- Финальное состояние: локальный main содержит рабочие пути apiship; сервер после
  `git pull` имеет чистый `git status` и то же содержимое файлов.

## Ограничения

- Локальной PHP-среды нет (`.agents/STACK.md`); runtime-проверки только на сервере.
- Push выполняется только после явного согласования с пользователем (скилл `git-sync`).
- На сервере не использовать `git clean -fd`/`-x` вслепую (правило `STACK.md`).

## Критерии Приёмки

1. В main закоммичены рабочие пути ApiShip (`admin/`, `catalog/`, `system/library/apiship/`), идентичные серверным (или пакету — при совпадении).
2. Кастомные патчи Measoft (`getWeight()`, `paytype`) присутствуют в рабочих файлах на сервере после синхронизации.
3. `git status` на сервере чистый (или содержит только осознанно оставленные runtime-файлы).
4. Природа изменения `bootstrap.css` разобрана и задокументирована (коммит или откат).
5. Задача 1.5 закрыта по шагу B4 (установка на сервере), `.agents` обновлён.
