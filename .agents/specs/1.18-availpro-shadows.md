# Задача 1.18 — Тени OCMOD availpro без Refresh (кнопка «Сообщить о поступлении» на dev)

**Задача:** 1.18-availpro-shadows
**Дата:** 2026-09-30
**Статус:** в работе

## Цель

Вернуть на витрину dev кнопку «Сообщить о поступлении» у товаров не в наличии (модуль «SM Уведомить о наличии PRO 9.7.1», включён в 1.17), применив OCMOD-модификацию `system/availpro.ocmod.xml` вручную — сборкой файлов-теней в `system/storage/modification/` и коммитом через `git add -f`, без использования запрещённого Refresh (аудит 1.15). Прецедент — восстановление теней ApiShip в 1.14.

## Контекст

- Модуль включён (`module_avail_status=1`), все 35 настроек `avail_*` в БД есть, лицензия доменная (гейтит только админ-страницу настроек, витрине не мешает).
- `avail.js`/`availability.css` УЖЕ подключаются на витрине (layout-привязка из боевой копии БД) — проверено на product_id=14517.
- Нет только OCMOD-хуков: скрытых `aval-product-quantity`-div'ов (данные для JS) и модалки `edit-modal-avail` в футере.
- Модификация НЕ установлена в `oc_modification` — и НЕ будет устанавливаться: XML уже лежит в `system/*.ocmod.xml` и применяется механикой refresh; DB-копия дублировала бы патчи при гипотетическом refresh.

## Требования

1. Реплицировать механику refresh OC 3.0.3.2 (`admin/controller/marketplace/modification.php:refresh`) ПОСТРОЧНО: glob(GLOB_BRACE), CRLF→LF, stripos-матчинг (без учёта регистра), str_replace (с учётом) для replace, index/offset/trim-атрибуты, error=skip/break/abort, запись только изменённых файлов, LF-окончания.
2. Вход — оригиналы из git (пересечений с существующими 26 тенями нет: те — checkout/information/admin-orders, availpro — product/category/footer/account/captcha/model).
3. Осознанный оверрайд: операция `catalog/controller/captcha/google_captcha.php` содержит синтаксическую ошибку вендора в add-коде (`$data.avail_config_google_captcha_status']`) — не применять, задокументировать (сломанный PHP в тени недопустим; капча на сайте не задействована).
4. Проверить каждый не-`error=skip` search на существование до применения (not-found без атрибута = break оставшихся операций файла — потеря патчей).
5. Смоук-тест после деплоя: товар не в наличии (14517 «Беретта») — кнопка «Сообщить о поступлении»; товар в наличии — «Купить»; главная/категория/чекаут — без ошибок.

## Ограничения

- Refresh Модификаторов запрещён (1.15) — не использовать.
- Не трогать DB (`oc_modification` не меняем — см. контекст).
- Тени коммитить только `git add -f` (правило .gitignore `system/storage/modification/**`).

## Критерии Приёмки

- Тени созданы скриптом-репликой OCMOD, каждая = оригинал + патчи availpro; список файлов и лог операций в implementation log.
- После git pull: кнопка у товара не в наличии работает (модалка открывается), у товара в наличии — «Купить»; сайт жив (главная, категория, карточка, чекаут).
