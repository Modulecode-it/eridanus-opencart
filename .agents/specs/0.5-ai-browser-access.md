**Задача:** 0.5-ai-browser-access
**Дата:** 2026-08-19
**Статус:** завершён

## Цель

Разрешить и формализовать прямое взаимодействие AI-агента с dev-сайтом
`eridanus.dev.modulecode.ru` через браузер (плагин browser-use): настройка
модулей в админке, runtime-проверки витрины, тестовые заказы — вместо передачи
всех этих шагов пользователю.

## Область

- Актуализация правил доступа в `AGENTS.md`, `.agents/STACK.md`,
  `.agents/CHECKLISTS.md`, скилле `no-local-testing`.
- Схема хранения кредов dev-админки для AI (отдельный AI-пользователь,
  gitignored-файл `.secrets/dev-admin.md`, шаблон в `.agents/templates/dev-secrets.md`).
- Правило обязательного предложения бекапа перед важными/разрушающими операциями.

## Предпосылки от владельца (2026-08-19)

- Сайт — **dev**, крутится на локальном сервере в Docker-проекте; на том же
  сервере другие сайты → **SSH-доступ выдать нельзя**.
- Браузерное обращение к dev-серверу — **без проблем, разрешено**.
- База скопирована с боевого сайта → для работы AI завести **нового пользователя
  админки**; логин/пароль можно хранить в файлах (это dev, опасений нет).
- Перед важными операциями на сайте — **сначала предлагать бекап** данных.

## Требования

1. **R1.** Правила проекта явно разрешают браузерное взаимодействие с dev-сайтом
   и явно фиксируют отсутствие SSH (не запрашивать).
2. **R2.** Креды dev-админки хранятся в файле вне git (`.secrets/`, `.gitignore`),
   т.к. репозиторий пушится на GitHub; в `.agents` секреты по-прежнему не попадают.
3. **R3.** Отдельный AI-пользователь админки (инструкция для владельца в шаблоне
   `dev-secrets.md`); основной аккаунт не используется.
4. **R4.** Перед важными/разрушающими операциями агент обязан предложить бекап
   (System → Maintenance → Backup → Export / Adminer) и дождаться подтверждения.
5. **R5.** База — копия боевой: правило «реальные заказы/данные клиентов не
   трогать без явного одобрения; тестовые сущности помечать; скриншоты и дампы
   не коммитить».

## Ограничения

- Локальный запуск PHP/БД/веб-сервера остаётся запрещён (среда — на dev-сервере).
- Внешние кабинеты (apiship.ru, Яндекс) — только по явной просьбе; секреты
  владельца вводит сам.
