# Спека 1.19 — Инцидент: перенос storage заказчиком через админку (dev)

Дата: 2026-10-12. Статус: в работе (диагностика завершена, ждёт серверных шагов Максима).

## Контекст

Заказчик (акк diona) при входе в админку dev регулярно видел окно безопасности OpenCart
с предложением перенести хранилище `storage` из webroot и выполнил перенос. После этого:

- на каждой странице админки — `Warning: fopen(/var/www/storage/logs/openbay.log)` и
  `eri_error.log` (нет каталога логов на новом пути);
- вход в админку фактически не работает (после отправки формы — белая страница);
- витринный чекаут показывает штатный OpenCart-флоу (Шаги 1–6) вместо SimpleCheckout
  одной колонкой (1.13), у заказчика дублируются поля региона/адреса;
- кнопка «выбрать ПВЗ» (Яндекс и 5Пост) «выкидывает на главную» (со слов заказчика);
- курьер Яндекс.Доставки при этом оформляется и виден в кабинете (подтверждение заказчика).

## Цель

1. Восстановить работоспособность dev: админка (вход без warnings), чекаут Simple,
   выбор ПВЗ на карте.
2. Вернуть git-состояние сервера к консистентному (tracked-тени
   `system/storage/modification/**` снова на месте).
3. Зафиксировать правило: перенос storage — только серверным шагом с бекапом,
   окно безопасности админки не трогать (dev и prod).

## Решение (принято)

**Откат переноса storage** на исходный путь `/var/www/html/system/storage/` (вариант A),
а не достройка нового пути. Причины:

- тени OCMOD живут в git по пути `system/storage/modification/**` — пайплайн деплоя
  (git pull раскладывает тени) рассчитан на этот путь; вынос storage из worktree его ломает;
- `config.php`/`admin/config.php` (gitignored) после откта возвращаются к исходным
  значениям `DIR_STORAGE`;
- недостающие каталоги (logs) на новом пути — лишь часть проблемы: warnings на каждый
  запрос сломали заголовки (redirect/setcookie после вывода), что и роняет вход в админку
  и AJAX чекаута.

Альтернатива-минимум (mkdir logs на новом пути) оставлена как временная мера, если откат
по какой-то причине невозможен — см. implementation log.
