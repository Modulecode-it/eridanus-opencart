# No local testing — среда запуска на удалённом dev-сервере

Проект (OpenCart 3.0.3.2) — **dev-копия**, развёрнутая на удалённом dev-сервере
в Docker-проекте (там же другие сайты). Локально нет ни рабочей среды запуска
сайта, ни БД, ни веб-сервера. Запрет касается **только запуска PHP-приложения и
серверной архитектуры локально** (OpenCart, MySQL/MariaDB, веб-сервер).

## НЕ делай локально — PHP и серверная архитектура

- `php -S` и любые попытки «поднять OpenCart» локально
- `mysql` / `mariadb` / поднятие БД
- Веб-сервер (Apache/Nginx) и поднятие его локально
- Любые попытки «проверить на ходу» запуском приложения локально

## Браузерная работа с dev-сайтом — РАЗРЕШЕНА (задача 0.5)

Владелец явно разрешил браузерное взаимодействие с dev-сайтом. Правила:

- Открывай `eridanus.dev.modulecode.ru` (витрина и админка) через плагин
  browser-use: настройка модулей, проверки, тестовые заказы, скриншоты.
- Креды админки — `.secrets/dev-admin.md` (в `.gitignore`); отдельный
  AI-пользователь, не основной аккаунт.
- **База — копия боевой**: реальные заказы/данные клиентов не менять без явного
  одобрения; тестовые сущности помечать.
- **Перед важными/разрушающими операциями** (удаления, установка/удаление
  модулей, массовые правки, SQL) — предложить бекап
  (System → Maintenance → Backup → Export либо Adminer) и дождаться подтверждения.
- **SSH к серверу НЕТ** (там другие сайты): `git pull` на сервере, cron,
  рестарты — формулируй как инструкцию для пользователя.
- Внешние кабинеты (apiship.ru, Яндекс) — только по явной просьбе, секреты
  вводит пользователь.

Подробности — `STACK.md`, секция «Браузерный Доступ к Dev-Сайту (AI)».

## Что МОЖНО локально — статические проверки

Если проверка **не запускает** PHP/БД/веб-сервер и не зависит от окружения OpenCart,
её можно выполнять локально:

- `php -l <file>` — если PHP установлен локально как бинарник (проверь заранее;
  на текущей машине PHP отсутствует — `php -v` не работает, тогда пропусти этот
  пункт). Это чистый lint синтаксиса, приложение не запускается.
- `bash -n script.sh` — синтаксис bash-скриптов.
- Валидаторы JSON/XML (в т.ч. проверка синтаксиса `.ocmod.xml` разбором текста), YAML.
- Twig-шаблоны — разбор текстом (структура, переменные, ссылки), без рендера.
- AST-утилиты проекта — в первую очередь `graphify update .` / `graphify query ...`
  (Python, работает локально без API-цены).
- Проверка регулярных выражений, форматов конфигов, имён/структуры файлов,
  целостности ссылок в документации.
- Чтение кода, разбор маршрутов/контроллеров/моделей OpenCart как замена запуску.

## Как выполняются runtime-проверки

- **Браузерные** (витрина, админка, расчёт доставки, тестовый заказ) — агент сам
  через browser-use на dev-сайте.
- **Серверные** (git-команды на сервере, cron, рестарт контейнеров) — пользователь
  по пошаговой инструкции агента; SSH из среды агента недоступен.
- Статические проверки выполняются локально; в отчёте явно отмечается, что именно
  прогналось (например: «проверил XML-синтаксис `system/tweak.ocmod.xml`»,
  «прогнал `graphify update .`», «проверил в браузере: Modifications → Refresh»).

## Если пользователь явно просит «запусти локально» PHP/сервер

Уточни, что локальной среды запуска в этом проекте нет, и предложи варианты:
браузерная проверка на dev-сайте (для витрины/админки), серверные шаги вручную,
либо статический разбор кода здесь (см. выше). Не пытаться «всё-таки» поставить
PHP/БД/веб-сервер — это не требуется.
