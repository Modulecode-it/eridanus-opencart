**Дата:** 2026-09-18
**Статус:** завершена (хотфикс задеплоен, серверные проверки зелёные; финальная браузерная проверка — за заказчиком)

## Симптом

В чекауте не появляются способы доставки («Вы должны выбрать способ доставки!»
при пустом блоке), поля «теряются», оформление невозможно.

## Цепочка расследования (день, с участием заказчика на сервере)

1. Прямые AJAX-роуты блоков `checkout/simplecheckout_shipping` и
   `checkout/simplecheckout_shipping_address` отдавали **HTTP 500 (пустое тело,
   0.2с)**; customer/payment/cart — 200.
2. PHP-fatal найден в `docker logs eridanus-apache` →
   `/var/log/apache2/php_errors.log`:
   `Uncaught Error: Call to a member function hasShipping() on null in
   catalog/controller/checkout/simplecheckout_shipping.php:13`.
3. Причина: в этих двух контроллерах Simple 4.11.9 синглтон
   `SimpleCheckout` использовался (`$this->simplecheckout->…`) ДО его создания
   (`loadLibrary + getInstance` ниже по коду). На прямых AJAX-запросах блоков
   (а именно ими обновляется чекаут) реестр пуст → null → fatal.
4. Попутно проверены и исключены: тарифы ApiShip (живы), настройки Simple
   (восстановлены после `[[]]`-инцидентов), modification-копии (вернули к git-
   snapshot: `git checkout -- system/storage/modification/` + `git clean -fdx`
   внутри каталога), Redis (не используется), сессии БД (InnoDB, пишутся),
   «корзина пуста» в моих тестах (артефакт 301-редиректов без `-L` в curl).

## Исправление

Коммит `22039ff`: в обоих контроллерах инициализация
(`loadLibrary('simple/simplecheckout')` + `SimpleCheckout::getInstance`)
перенесена ВВЕРХ, до первого обращения к `$this->simplecheckout`.
Сервер обновлён (`git pull`, fast-forward).

## Хвосты (отдельные задачи)

- **Дубли событий СДЭК в `oc_event`** (~60 копий каждого `cdek_shipping_*`
  события, id 46–349) — лишняя нагрузка на каждый запрос. Чистка:
  `DELETE e1 FROM oc_event e1 INNER JOIN oc_event e2 ON e1.code=e2.code AND
  e1.action=e2.action AND e1.trigger=e2.trigger AND e1.event_id>e2.event_id;`
- **Не нажимать «Обновить» в Модификаторах** без сверки: текущий набор OCMOD
  в БД не воспроизводит легаси-состояние modification-каталога (мой refresh
  уже ломал Simple). Техдолг: сверить моды, отключить лишние (СДЭК-события
  частично от них), затем обновить и зафиксировать каталог в git.
- Настройки Simple: вернуть ПВЗ-набор полей `apiship.point*|` (город без
  индекса/адреса) — был удалён при бисекции; страна по умолчанию РФ;
  индекс — необязательным.
- `error_display` выключен (вывод PHP-ошибок в тело ответа ломал AJAX).
