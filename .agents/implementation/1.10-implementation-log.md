### Детали изменения 5 (через API настроек Simple)

Редактор наборов полей в админке Simple (Vue SPA) не поддался UI-автоматизации
(drag&drop палитры полей); изменения внесены прямым вызовом того же API, которым
пользуется сама админка:

- GET `admin/index.php?route=extension/module/simple/settings&user_token=…&token=…`
  → объект настроек; путь: `d[0].checkout[0].shippingAddress.rows.default`;
- в массив добавлены элементы вида
  `{"displayWhen":[],"hideForGuest":false,"hideForLogged":false,"id":"city","masterField":"","requireWhen":[],"required":1,"sortOrder":2,"type":"field"}`
  (и аналогичный для `address_1`);
- POST тот же URL, body `{"settings": "<json>"}` → `{"success":true}` (HTTP 200).

`addressSelectionFormat` («{firstname} {lastname}, {city}, {address_1}») не менялся.

### Промежуточные артефакты UI-попыток

## Дополнение 3 (2026-09-08, восстановление настроек Simple — завершено)

Причина порчи настроек установлена: API `/settings` ожидает settings в виде
массива-обёртки `[<объект групп>]`, вчерашний POST отправил объект групп без
обёртки → сервер сохранил `[[]]` (пусто). Симптомы: витрина без блоков,
админка показывала дефолты, GET `/settings` → `[[]]`.

Восстановление (browser-use, окно транспорта):

1. Вход в админку, открытие Simple.
2. Клик «Сохранить» оказался холостым (SPA не считает модель изменённой,
   ничего не постит).
3. Решение: двойное переключение тумблера «Требовать авторизацию» (модель
   стала «грязной») → «Сохранить» → POST прошёл.
4. Верификация GET `/settings` — настройки на месте, структура валидна:
   - `guestCheckoutDisabled: false` (гостевой заказ разрешён);
   - набор полей «Адрес доставки»: `address_id` (необязательное, скрыто для
     гостей) + `firstname`, `lastname`, `country_id`, `zone_id`, `city`,
     `postcode`, `address_1` — все обязательные, видны гостям;
   - `hideForPaymentMethods` — пусто (блок адреса не скрывается для COD).

Итог по правкам задачи (всё в БД dev, код не менялся):

| Правка | Статус |
|---|---|
| Гостевой заказ разрешён | ✅ (`guestCheckoutDisabled=false`) |
| Measoft ×2 выключены | ✅ (список расширений перепроверен после рестарта) |
| `shipping_apiship_title` = «Доставка по России» | ✅ (значение в oc_setting, рестарт не затронул) |
| Поля Города/Адреса в чекауте | ✅ (восстановлены, обязательные) |
| COD геозона = «Все регионы» | ✅ (сохранено и перечитано) |
| Скрытие адреса для COD снято | ✅ (hideForPaymentMethods пуст) |

Витринная проверка рендера блоков после восстановления не завершена

## Дополнение 4 (2026-09-08, ПВЗ без адреса доставки)

Запрос заказчика: зачем «Адрес доставки» (Индекс*/Адрес*) при выборе
«Самовывоз из ПВЗ Яндекс.Доставка» — товар едет в ПВЗ с карты.

Решение — штатный механизм Simple «наборы полей по условию»: у блока
«Адрес доставки» создан второй набор с условием `apiship.point*|`
(маска способа доставки | маска оплаты; формат выведен из
`admin/view/javascript/simple.js`, функция addCondition) с полями только
для ПВЗ: `address_id, firstname, lastname, country_id, zone_id, city`
(без `postcode`/`address_1`). Набор «По умолчанию» (полный, для курьера)
не менялся. Маска `apiship.point*` покроет и будущий 5Пост (`point_x5_*`).

Как внесено: браузерный транспорт деградировал, поэтому правка сделана
через живую модель SPA: в Vuex-сторе (`__vue__.$store.state`) найден объект
настроек магазина, добавлен ключ в `shippingAddress.rows`, затем вызван
штатный `store.dispatch('SAVE_SETTINGS')` → `{"success":true}`.
Контрольный GET `/settings` — объект на месте (24.9 КБ), ключи rows:
`default` + `apiship.point*|`.

Попутно выяснено: после рестарта сервера хранилище настроек Simple было
пустым (`[[]]`, витрина работала на дефолтах — скриншот заказчика это
подтверждает). Настоящее сохранение из SPA записало ПОЛНЫЙ объект —
настройки теперь хранятся явно, а не живут на дефолтах.

Важно на будущее: сырой POST в `/settings` из скрипта небезопасен (писал
не в то представление — см. Дополнение 3); надёжный путь — мутация
Vuex-модели + `dispatch('SAVE_SETTINGS')` на странице админки Simple.

Рантайм-поведение (исчезновение Индекс/Адрес при выборе ПВЗ-метода,
возврат при выборе курьера) на витрине не проверено из-за транспорта —
проверка за заказчиком: выбрать «Самовывоз из ПВЗ Яндекс.Доставка» в
чекауте → поля «Индекс*» и «Адрес*» должны скрыться (останется Город*),
при выборе «Курьер Яндекс Доставка» — вернуться.
