# 1.13 — Чекаут: одна колонка + объединённый блок «Доставка и оплата»

Дата: 2026-09-19. Статус: завершён (применено на dev, проверено).

## Задача

По просьбе владельца перестроить страницу `checkout/simplecheckout`:
- все блоки на всю ширину страницы, без двух колонок;
- порядок сверху вниз: заголовок «Оформление заказа» (заголовок страницы) → Покупатель → Адрес доставки → один блок, объединяющий «Способ доставки» и «Способ оплаты» → Комментарий.

## Как устроена раскладка (находка)

Вся раскладка чекута Simple 4.11.9 задаётся строкой-шаблоном в настройках модуля:
`settings.checkout[0].steps[0].template` (в Vuex сторе — `state.settings[0]...`).
Шаблон `catalog/view/theme/default/template/checkout/simplecheckout.twig` (строка `{{ simple_template|replace(replace) }}`) подставляет вместо плейсхолдеров HTML блоков: `{cart}`, `{customer}`, `{shipping_address}`, `{shipping}`, `{payment}`, `{comment}`, `{payment_form}`, а также колоночные обёртки `{left_column}…{/left_column}`, `{right_column}…{/right_column}`, `{three_column}`, `{step}`.

Старое значение (две колонки):

```
{left_column}{cart}{customer}{shipping_address}{/left_column}{right_column}{shipping}{payment}{comment}{/right_column}{payment_form}
```

## Что сделано

Новое значение (одна колонка, склейка доставки и оплаты в один блок, стили подзаголовков — инлайн `<style>` в том же шаблоне):

```
<style>#simplecheckout_delivery_payment .simplecheckout-block{margin:0}#simplecheckout_delivery_payment .simplecheckout-block .checkout-heading{background:none;border:none;border-radius:0;padding:0 0 8px;font-weight:bold;font-size:14px}#simplecheckout_delivery_payment .simplecheckout-block .simplecheckout-block-content{padding:0}#simplecheckout_delivery_payment #simplecheckout_shipping{padding-bottom:14px;border-bottom:1px solid #e5e5e5}#simplecheckout_delivery_payment #simplecheckout_payment{padding-top:14px}</style>{cart}{customer}{shipping_address}<div class="simplecheckout-block" id="simplecheckout_delivery_payment"><div class="checkout-heading panel-heading">Доставка и оплата</div><div class="simplecheckout-block-content">{shipping}{payment}</div></div>{comment}{payment_form}
```

Дизайн: у внешнего блока `#simplecheckout_delivery_payment` — штатная серая полоса заголовка «Доставка и оплата»; внутри — подзаголовки «Способ доставки»/«Способ оплаты» жирным текстом без фона (переопределение `.simple-content .checkout-heading`), между секциями тонкий разделитель `#e5e5e5`. Корзина (`{cart}`) осталась первой — владелец её порядок не менял; `{payment_form}` (форма оплаты картой) — в конце.

Изменение внесено единственным безопасным путём: в админке Simple (`route=extension/module/simple`, Vue SPA) мутация `$store.state.settings[0].checkout[0].steps[0].template` + `dispatch('SAVE_SETTINGS')` → `{"success":true}`. Повторный GET `route=extension/module/simple/settings` подтвердил значение на сервере. Кода PHP/Twig/CSS не менялось — файлы репо не тронуты, git-деплой не требуется.

Бэкап настроек до изменения: `.agents/analysis/1.13-simple-settings-backup-before-layout-2026-09-19.json` (полный GET /settings; секретов нет). Откат = вернуть старое значение template из бэкапа тем же способом.

## Проверка (браузер, dev)

- Гость, товар в корзине (пазл 229р.): DOM содержит ровно один `.simplecheckout`, порядок блоков `cart → customer → shipping_address → delivery_payment → comment → payment_form`; колоночных обёрток нет; все верхнеуровневые блоки 1130px при вьюпорте 1440px.
- В `#simplecheckout_delivery_payment` внутри: `#simplecheckout_shipping` + `#simplecheckout_payment`, заголовок «Доставка и оплата».
- После ввода города (Страна РФ + «Санкт-Петербург») и AJAX-перезагрузки блоков методы приходят и остаются внутри объединённого блока: «Самовывоз Яндекс.Доставка 3дн. - 162р.», «Курьер Яндекс.Доставка 3дн. - 320р.»; оплата: «Оплата при доставке», «Оплата картой на сайте банка».
- Скриншоты: подзаголовки жирные без фона, разделитель есть, кнопка «Оформить заказ» на месте, дефектов вёрстки нет.
- Прямой POST `route=checkout/simplecheckout_shipping` с данными формы — 200, 2 radio-метода.

Примечание: при синтетическом заполнении (программная установка значений) первый reload мог прийти со старой сессией — при живом вводе (fill+blur) город сохраняется и методы подгружаются штатно.
