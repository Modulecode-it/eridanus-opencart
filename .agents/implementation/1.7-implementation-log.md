### Проблемы, выявленные при тесте экспорта (важно для клиента)

1. **Наложка на экспресс-тарифах Яндекса запрещена** (заказ #6712, тариф 562): ApiShip API
   отклонил `cost[codCost]` — «Наложенный платеж недоступен на экспресс тарифах».
2. **Наложка картой у курьера Яндекса не поддерживается**: следующий отказ для #6713 —
   «Payment method 'card' is not allowed for courier delivery». Модуль не передаёт способ
   оплаты наложки (paymentMethod), ApiShip по умолчанию подставляет card, а Яндекс-курьер
   принимает только наличные. **Вывод: полноценная наложка через Яндекс-курьера этим
   модулем без доработки невозможна; работает только предоплата** (R8 — решить клиенту:
   предоплата, ПВЗ-наложка или доработка модуля).
3. Для приёмочного теста наложка отключена через настройки: «Наложенный платеж» →
   «Оплаченные заказы (статусы)» = «Доставлено», «Подтвердить оплату» → заказы в этих
   статусах экспортируются как предоплаченные (codCost=0).
4. Габариты/вес: при выгрузке обязательно передавать вес (целое, граммы) — в карточке
   заказа поля «Вес всего заказа» могут быть пустыми, тогда ApiShip отвечает ошибкой
   валидации. Тестовая выгрузка: 10×10×10 см, 500 г.

### Особенность выгрузки (кнопка в карточке заказа)

Кнопка «Создание заказа в Apiship» (`#shipping_apiship_export`, OCMOD в
`sale/order/info`) шлёт AJAX на catalog-роут
`index.php?route=extension/shipping/apiship/export_order&id=<order_id>&key=<cron_key>`
с параметрами формы (тип забора 1=курьер/2=привоз на склад СД, габариты, вес, комментарий,
дата). Роут требует сессию админа (`session->data['user_id']`) и cron_key. В сессии
браузера плагина клики по кнопке нестабильно доходили до jQuery-обработчика — рабочий
обход: открыть URL выгрузки напрямую в залогиненной админской вкладке с параметрами:
`...&shipping_apiship_pickup_type=2&shipping_apiship_place_length=10&shipping_apiship_place_width=10&shipping_apiship_place_height=10&shipping_apiship_place_weight=500&shipping_apiship_comment=TEST+AI&shipping_apiship_pickup_date=`.

## Технические детали и находки

- **Формат токена ApiShip** — 32-hex строка из поля Api Token на дашборде ЛК `a.apiship.ru`
  (не eyJ-JWT, ожидание из 1.5 устарело). Токен передаётся в заголовке `Authorization: <token>`
  без Bearer (см. `system/library/apiship/apiship.php`).
- **Endpoint'ы**: `lists/providers` (33 службы), `connections` (подключения ЛК), `lists/statuses`,
  `lists/points` (ПВЗ). Модуль показывает во вкладке провайдеров только службы из `connections`.
- **Кэш модуля** — PHP-сессия (`$_SESSION['shipping_apiship']`, TTL 10 мин, см. setData/getData):
  после подключения Яндекса в ЛК вкладка провайдеров ожила не сразу, а после истечения кэша.
  Logout в OC 3.0.3.2 сессию НЕ убивает (только unset user_token) — перелогин не сбрасывает кэш.
- **Лог модуля** — `$this->log->write()` → error.log, виден в админке System → Maintenance →
  Error Logs. Ошибки API пишутся всегда (`error=true`).
- **Поиск точки приёма** в модуле идёт по префиксу КОДА ПВЗ (`code%`), не по адресу. Точку
  Планерная 47 нашли через API-фильтр `providerKey=yataxi;city=Санкт-Петербург;address%Планерная`.
- **Тонкости чекаута (Simple)**:
  - Реальная кнопка заказа — клон платёжной кнопки `[data-payment-button=true]` (#button-confirm),
    исходная `#simplecheckout_button_confirm` скрыта через inline style (simplecheckout.js:600).
  - Radio доставки сохраняется AJAX'ом по change; клик по УЖЕ отмеченному radio не генерирует
    change (нужно переключить на другой метод и обратно).
  - В чекауте активны и старые методы (flat, measoftcourier ×2 — Е-Логистик закрыта клиентом,
    MeaSoft в backlog на отключение).
- **Витрина, добавление в корзину**: клик `#button-cart` через Playwright регулярно падает с
  `Browser broker response id mismatch`; рабочий вариант — увеличить viewport (кнопка ниже
  720px) и клик `cua.click` по координатам. После добавления всплывает alert — закрывать
  через `getJsDialog().dismiss()`.
- **Товар для тест-заказов**: Тауэрский мост TG412 (product_id 216986?) реально сток 0 при
  метке «В наличии» (статус ≠ остаток). Использован «Миниатюрный дом Гостиная DGM01»
  (product_id=11993, сток 146, 6320р.).
- **Заказ #6710**: статус «Доставлено» (странное значение по умолчанию для нового заказа —
  проверить настройки статусов магазина; в чекауте выбирались flat+cod).
