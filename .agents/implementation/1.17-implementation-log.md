### Фикс (код)

**Файл:** `catalog/model/extension/shipping/apiship.php` (+12/−3 строк)
**Причина:** Simple рендерит блок доставки до блока оплаты (`paymentBeforeShipping` не задан → false), поэтому `session->data['payment_method']` в момент `getQuote` содержит предыдущее состояние.
**Описание:** новый приватный `get_payment_method_code()` — при AJAX-перезагрузке чекаута берёт оплату из `$this->request->post['payment_method']` (reloadAll шлёт всю форму), fallback на сессию. Заменены 3 места чтения: `get_quote_list` (рендер блока), `get_points_array` (карта ПВЗ), `set_point` (выбор точки). Тени OCMOD у модели нет.
**Побочные эффекты:** в админ-контекстах POST `payment_method` содержит title («Оплата при доставке»), а не код — `in_array(..., ['cod'])` даёт false, как и прежняя пустая сессия — поведение не меняется. При блочной перезагрузке только блока доставки POST не содержит оплату — fallback на сессию (как сейчас).
### Проверка: локально `php -l` невозможен (нет PHP) — баланс скобок проверен; **runtime-проверка ВЫПОЛНЕНА 2026-09-30 после git pull на dev** (сервер обновлён до 4c36ba0):

| Шаг | Оплата выбрана | Методы доставки |
|---|---|---|
| начальный рендер | «при доставке» (cod, автозапуск) | 5Post + Яндекс ПВЗ + курьер (первичная GET-загрузка без POST — котировки по пустой сессии, известный артефакт первой загрузки; после любого обновления блока соответствие точное) |
| переключение на «картой» | modulbank | 5Post + Яндекс ПВЗ + **курьер 329р.** ✓ (до фикта курьер именно здесь пропадал) |
| обратно на «при доставке» | cod | 5Post + Яндекс ПВЗ, **курьер исчез сразу** ✓ (до фикса здесь ошибочно появлялся) |

Лаг сессии на переключениях оплаты устранён; поведение «нал=только ПВЗ» срабатывает мгновенно в обе стороны. Замечание: на самом первом рендере чекаута (GET без POST) при пустой сессии список может показывать курьера при автовыбранном нале — не регрессия (существовало и до фикса), лечится любым обновлением блока; при желании можно дожать позже чтением payment_method из сессии при её отсутствии в POST (сейчас так и есть — fallback).

### Альтернатива, отклонённая

## ⚠️ Инцидент: порча `simple_settings` при массовом импорте oc_setting (исправлено)

**Что случилось:** для включения `module_avail_status` был выполнен TRUNCATE+INSERT всей `oc_setting` через штатный route=tool/backup/import (модифицированный дамп экспорта). После этого `simple_settings` (26КБ JSON) перестал декодироваться: чекаут — пустой шаблон без блоков, админка Simple — пустая оболочка, `GET route=extension/module/simple/settings` → `[null]`.

**Механика:** парсер импорта (fgets по строкам, `substr($line,-2)==";\n"`, батчи по 100) исказил значение большой JSON-строки при полном цикле экспорт→импорт. Полный разбор механизма не завершён; строки с простыми значениями прошли без изменений (проверено по 608→608 строкам и контрольным ключам apiship/cod — целы).

**Восстановление:** из бэкапа настроек 1.13 (`.agents/analysis/1.13-simple-settings-backup-before-layout-2026-09-19.json`) + дельты: финальный шаблон 1.13 (одна колонка, объединённый блок «Доставка и оплата») и ПВЗ-набор полей 1.14 `apiship.point*|` → файл `.agents/analysis/1.17-simple-settings-repaired.json` → POST `route=extension/module/simple/settings` form-urlencoded `{settings: JSON.stringify([настройки])}` (формат подсмотрен в бандле simple.js: vue-resource `post(adminApi+"/settings",{settings:...})`; первая попытка JSON-телом записала пусто — исправлено). Модуль сам пересохранил все simple_* строки корректно (новые setting_id 290023–290045). Чекаут восстановлен (все блоки), API отдаёт 25.6КБ валидного JSON.

**Проверено после восстановления:** все блоки чекаута, шаблон одной колонки, ПВЗ-набор полей (скрытие Индекса/Адреса у point-методов), котировки, ключевые настройки (`shipping_apiship_cash_on_delivery_payment_methods=["cod"]`, `payment_cod_order_status_id=1`, `shipping_apiship_description_point_template=''`).

**Правило на будущее (занесено в STACK.md):** НЕ использовать route=tool/backup/import для TRUNCATE+INSERT больших таблиц настроек. Точечные однострочные INSERT — ок (проверены). Изменение настроек сторонних модулей — через их собственные API/формы.

**Хвост по данным:** в `oc_setting` 3 строки `module_avail_status` (27930='1', 289999='0', 290050='1' — последняя выигрывает, модуль включён). Не критично; чистка опциональна через Adminer: `DELETE FROM oc_setting WHERE \`key\`='module_avail_status' AND setting_id IN (27930,289999);`
