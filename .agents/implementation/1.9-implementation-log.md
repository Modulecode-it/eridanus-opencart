**Диагностика отсутствия методов 5Пост в чекауте** (главный результат сессии):

8. Чекаут (simplecheckout, тест-покупатель, корзина 6620р.) показывает
   только `point_yataxi_…`/`door_yataxi_…` — методов `point_x5_*` нет.
9. Захват реального запроса через error.log (режим «Отладка»): модуль шлёт
   `POST https://api.apiship.ru/v1/calculator` (UTF-8, заголовки
   `Platform: opencart_v3`, `Authorization: <token>`, `Accept: application/json`),
   в ответе ApiShip возвращает блок `providerKey=x5` **с пустым массивом
   tariffs** в deliveryToPoint и deliveryToDoor (у yataxi тарифы есть).
10. Прямые пробы API калькулятора (python urllib, UTF-8): x5=0 тарифов во
    всех вариантах — с/без `extraParams`, с `codCost`, `includeFees`,
    датами сдачи (01/02/08.09), другим городом (Москва), меньшим весом.
    Передача `x5.pointInId=<uuid склада>` отклоняется: «Пункт приема x5 не
    соответствует указанной СД» (склад ≠ пункт приёма — подтверждает
    стратегию «не передавать pointInId для x5»).
11. Штатный калькулятор ЛК ApiShip (Откуда: Планерная 47 к 1 — подтянулись
    координаты нашего склада; Куда: Невский пр-кт 28) — тот же результат:
    `x5 tariffs: []`, у yataxi тариф есть. Т.е. блок не в модуле, а в
    готовности подключения на стороне ApiShip/5Пост.
12. Справочник ПВЗ при этом уже наполнен: `lists/points?providerKey=x5`
    возвращает точки «…- Пятерочка» (type 1) по всей РФ — значит, провайдер
    прогружен, ожидаем именно тарифную сетку/активацию.
13. Побочные находки:
    - Кэш калькулятора модуля живёт в PHP-сессии storefront и его hash НЕ
      включает флаги провайдеров (pickup/courier) — смена настроек модуля
      не инвалидирует кэш; для свежего расчёта менять корзину/адрес или
      ждать TTL (10 мин).
    - curl из Git Bash (Windows) с кириллицей в `-d` уходит в неправильной
      кодировке → ApiShip отвечает HTTP 400 «Неправильная кодировка»;
      тело писать в UTF-8-файл и слать `--data-binary @file`, либо python urllib.
    - Метод вида `point_<prov>_<tariff>_error_<pt>` — штатная «заглушка»
      модуля (ПВЗ ещё не выбран), это не ошибка.

**Вывод**: подключение выполнено полностью и корректно (ключ, partnerId,
склад, провайдер в модуле, маппинг покрывает). Тарифы x5 в ApiShip ещё не
активированы (подключению ~1 час; ApiShip/5Пост заявляли подключение «за

требуется. Далее: тест-заказ + выгрузка (R6).
