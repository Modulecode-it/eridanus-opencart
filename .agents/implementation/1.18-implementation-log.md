# Журнал реализации 1.18 — Тени OCMOD availpro без Refresh

**Задача:** 1.18-availpro-shadows
**Дата:** 2026-09-30
**Статус:** завершён

## План

Разбор availpro.ocmod.xml → реплика механики refresh → генерация теней → деплой → живая проверка. Выполнено с одной существенной корректировкой курса (см. «Поворот»).

## Что сделано

### 1. Разведка

- `avail.js`/`availability.css` уже подключаются на витрине (layout-привязка модуля из боевой копии БД) — не хватало только OCMOD-хуков.
- Инвентаризация `system/availpro.ocmod.xml`: ~20 групп целей (контроллеры product/category/manufacturer/search/special/compare/wishlist, wildcard по `catalog/controller/extension/module/*.php` (6 совпадений), model/catalog/product, footer, account, админ-товары, 9 языковых, шаблоны default; цели ft_frame/journal3/captcha в репо отсутствуют).
- Изучена механика refresh (`admin/controller/marketplace/modification.php`): построчные операции (stripos-матчинг без учёта регистра, str_replace с учётом), GLOB_BRACE, `trim` по умолчанию включён, index на `<search>` (вендор ошибочно ставил на `<add>` — refresh такое игнорирует), error=skip/break/abort, запись только изменённых файлов с LF.

### 2. Генерация (коммит cc968da)

`.agents/analysis/1.18-apply-availpro.py` — точная реплика механики; dry-run → ревью → 42 тени (`git add -f`). Все обязательные search-строки найдены, диффы выборочных файлов корректны, баланс скобок чист. Живая проверка после pull: **twig-тени применились (div'ы в HTML), PHP-контроллерные — нет** (`{{ product_id }}` выводится, `{{ avail_product_quantity }}` — пусто).

### 3. Поворот: причина и перенос патчей (коммит c5c2912)

**Корневая причина:** в этой сборке теневой `system/engine/loader.php` вызывает `modification()` только в `model()`/`library()`/`helper()`; метод **`controller()` подключает контроллеры всегда из оригинала**, языковая подмена аналогично неактивна. Шаблонная подмена работает через отдельный механизм (Template engine → `system/library/template/twig.php`). Т.е. контроллерные/языковые тени на этом сайте в принципе не исполняются.

Решение: PHP-патчи availpro перенесены из теней в **оригинальные файлы** (26 шт.: 17 контроллеров витрины, 1 админ-контроллер, 1 модель, 9 языковых — скрипт `.agents/analysis/1.18-move-php-to-origins.py`), неиспользуемые 26 php-теней удалены (задвоение при гипотетическом refresh), **16 twig-теней оставлены** в `system/storage/modification` (работают). Vendor-операции по captcha-файлам не применялись (файлы отсутствуют в репо).

## Проверено на живом dev (после обоих pull)

- **Товар не в наличии** («Беретта», 14517): qty=0 в скрытом div, `avail.js` подменил кнопку — `<button class="notify_product">Заказать</button>` (текст — настройка `avail_text.button_avail` с прода); клик → **модалка `edit-modal-avail` открывается** (form#notify: product_id, имя, E-Mail, количество, комментарий). Скриншот в артефактах сессии.
- **Товар в наличии** (Попугай, 13264): qty=1, кнопка «Купить» (#button-cart) на месте.
- **Категория** «3d пазлы животные»: 25 листинговых div'ов со значениями 1/0 — данные для кнопок в листингах идут.
- **Смоук**: главная 200, чекаут с товаром — блоки доставки/оплаты живы, PHP-ошибок нет нигде; чекаут при пустой корзине штатно показывает «корзина пуста».
- Админ: страница товара не проверялась на notify-цепочку (правка `editProduct` gated настройкой `avail_config_product_edit`).

## Открытые пункты

1. **Гипотеза для проверки:** контроллерная тень ApiShip `simplecheckout_shipping.php` (валидация «выберите ПВЗ» из 1.14) всё это время тоже могла не применяться. Сценарий: заказ ПВЗ-методом БЕЗ выбора точки — должна быть ошибка. Если проходит — валидацию перенести в оригинал тем же способом.
2. На проде при включении модуля текст кнопки будет «Заказать» (прод-настройка `avail_text.button_avail`); если заказчик хочет «Сообщить о поступлении» — поменять в настройках модуля (на dev страница настроек за лицензионным гейтом).
3. Гипотетический Refresh по-прежнему запрещён (аудит 1.15); при его будущем «разрешении» каталог пересоберётся с 200+ изменениями — перенос PHP-патчей в оригиналы эту картину не ухудшает.
