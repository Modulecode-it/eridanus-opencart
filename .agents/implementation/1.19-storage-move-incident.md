## Runbook для Максима (серверные шаги, docker на dev-хосте)

### Шаг 0. Диагностика (опционально, 30 сек)

```bash
docker ps --format '{{.Names}}' | grep -i eridanus     # имя php-контейнера
docker exec <php-контейнер> ls -la /var/www/storage      # что реально на новом пути
docker exec <php-контейнер> ls -la /var/www/html/system/storage 2>/dev/null || echo "старый путь пуст/удалён"
```

Ожидаемо: на новом пути есть `vendor/`, `session/`, `modification/`, `cache/`, нет `logs/`;
старый путь `system/storage` пуст или отсутствует (перенос сделал rename).

### Шаг 1 (основной). Откат переноса storage

```bash
docker exec <php-контейнер> bash -c '
  set -e
  mkdir -p /var/www/html/system/storage
  cp -a /var/www/storage/. /var/www/html/system/storage/
  rm -rf /var/www/storage
  mkdir -p /var/www/html/system/storage/logs
  chown -R www-data:www-data /var/www/html/system/storage
'
```

Затем в файлах `/var/www/html/config.php` и `/var/www/html/admin/config.php` вернуть
(правка руками или sed):

```php
define('DIR_STORAGE', '/var/www/html/system/storage/');
```

### Шаг 2. Проверка git-состояния worktree

```bash
cd /var/www/html && git status --short | head -20
```

Ожидание: tracked-тени `system/storage/modification/**` снова совпадают с git
(возможны untracked-хвосты от работы сайта — это норма, не удалять `git clean`).

### Шаг 3 (альтернатива-минимум, если откат невозможен)

```bash
docker exec <php-контейнер> mkdir -p /var/www/storage/logs
docker exec <php-контейнер> chown -R www-data:www-data /var/www/storage/logs
```

Убирает warnings и чинит вход/AJAX, НО оставляет тени вне git-пайплайна и storage
вне worktree (пропадёт при пересоздании контейнера). Только как временная мера.
