# 1.15 — Чистка дублей событий СДЭК + аудит OCMOD

Дата: 2026-09-19. Статус: завершён.

## 1. Дедупликация `oc_event`

Симптом: 5 событий модуля СДЭК (`cdek_shipping_add_scripts`, `cdek_shipping_success_order`, `cdek_shipping_order_create`, `cdek_shipping_order_history`, `cdek_shipping_check_tariff_pvz`) были зарегистрированы по 43 копии каждое (id 46–349) — лишние вызовы на каждом запросе.

Выполнено через Adminer (`adminer-4.7.3-mysql.php`; вход: server `host-eridanus`, пользователь/база `eridanus`, пароль — значение `DB_PASSWORD` из `config.php` репо, он и боевой на dev; SQL выполняется POST на `...&sql=SELECT` c `token` формы — длинные тексты Adminer режет, обход — `HEX(SUBSTRING(xml,...))`):

1. Бэкап всей таблицы до правки: `.secrets/backup-oc_event-2026-09-19.sql` (349 строк, INSERT-дамп; в git не попадает).
2. `DELETE e1 FROM oc_event e1 INNER JOIN oc_event e2 ON e1.code=e2.code AND e1.action=e2.action AND e1.\`trigger\`=e2.\`trigger\` AND e1.event_id>e2.event_id;`
3. Контроль: 349 → **139** строк, у каждого события ровно 1 копия, групп с дублями — 0. Смоук-тест после: главная и чекаут работают.

Замечание: сами 5 событий СДЭК оставлены (модуль установлен, хоть и выключен) — при желании можно снять с регистрации отдельно.

## 2. Аудит OCMOD (сверка БД ↔ каталог теней)

Метод: выгружены XML всех 22 включённых модов из `oc_modification` (HEX-кусками по 30К, сумма совпала байт в байт; лежат в `.secrets/mods-xml/<id>-<code>.xml`), скриптом `.secrets/mods-xml/virtual-refresh.mjs` выполнен «виртуальный Обновить» (порядок по modification_id, glob-маски, before/after/replace/index/trim; `<regex>` не поддержан — таких модов нет) и результат сравнён с текущим `system/storage/modification/`.

Верdict: **текущий каталог теней НЕ воспроизводим кнопкой «Обновить»**:

- Идентично (после нормализации CRLF): 4 файла;
- **Изменится содержимое: 11** — в т.ч. `catalog/controller/checkout/simplecheckout_shipping.php` и `shipping_method.php` (кроме ApiShip их патчат Filterit №21 и measoft №67), `admin/controller/sale/order.php` (Filterit+measoft+Yandex_beru №61), `system/engine/loader.php` (d_twig_manager №8), `system/library/template/twig.php` (№8+№61), `header.twig` (№15);
- **Будет удалено: 11** текущих теней — патчи выключенных модов (СДЭК №4, Facebook №5), чьи тени до сих пор «живые» в каталоге (легаси-состояние);
- **Появится: 182 новых файла** — широкие наборы Filterit (66КБ), optimblog №14 (258КБ), Yandex_beru №61 (62КБ), modification_manager №26 (25КБ) на массу admin/catalog контроллеров.

Так «Обновить» и ломал Simple в 1.12: полная перегенерация (~204 файлов) уходит от рабочего легаси-состояния.

Решение/правила:

1. **«Обновить» в Расширения → Модификаторы НЕ нажимать.** Текущее состояние — 26 теней, все в git (после 1.14), рабочее (проверено сквозным тестом заказа).
2. Отключённые моды (СДЭК №4, Facebook №5, Metrica №64) продолжают «жить» через старые тени 11 файлов — это осознанный легаси, не трогать без отдельной задачи.
3. Будущая нормализация (отдельная задача, только по решению владельца): аудит используемости Filterit/optimblog/Yandex_beru/modification_manager → выключить лишние → полный refresh → фикс каталога в git → сквозной тест.

## Артефакты

- `.secrets/mods-xml/*.xml` (22 шт.) + `virtual-refresh.mjs` + `expected/` — материал аудита (gitignored).
