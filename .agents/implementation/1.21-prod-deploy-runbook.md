## 2. БЕКАП ПРОДА (до любых изменений)

### 2.1 База данных — phpMyAdmin

1. Войти в phpMyAdmin (из ISPmgr: «Базы данных» → phpMyAdmin, либо ссылка хостера).
2. Слева выбрать базу магазина (имя — из продового `config.php`, константа `DB_DATABASE`).
3. Верхнее меню «Экспорт»: способ «Обычный», все таблицы, формат SQL,
   сжатие gzip (или zip) → «Вперёд» — дамп скачается на локальную машину.
4. Проверить дамп: файл не 0 байт; внутри есть `CREATE TABLE` и данные заказов.

### 2.2 Файлы кода — веб-шелл ISPmanager (основной путь)

```bash
cd /var/www/p646143/data/www/eridanus.ru
tar -czf "$HOME/code-backup-$(date +%Y%m%d-%H%M).tar.gz" \
  --exclude='./image' --exclude='./storage79' --exclude='./webstat' \
  --exclude='./system/storage/cache' --exclude='./system/storage/session' \
  .
ls -lh "$HOME"/code-backup-*.tar.gz        # ожидание ~25 МБ
tar -tzf "$HOME"/code-backup-*.tar.gz | head
```

Код+конфиги+`modification` входят; runtime и тяжёлые не-кодовые каталоги — нет.
Архив в `$HOME` (выше корня сайта) — публично не доступен. Затем скачать по FTP.
⚠️ Квота на диске исчерпана (см. шапку): перед tar освободить место —
`rm -rf ./image/cache/*` (миниатюры регенерируются) и/или скачать+удалить `storage79`.

Запасной путь без шелла — файловый менеджер: архивировать всё, кроме `image`,
`storage79`, `webstat`; либо скачать по FTP всё то же (~68 МБ). Продублировать
локально критичную мелочь: `config.php`, `admin/config.php`, `php.ini`, `.htaccess`.
Проверить панельные бекапы: ISPmgr → «Инструменты» → «Резервные копии».

### 2.3 Если архиватор панели не осилит

Скачать по FTP всё, кроме `image/` (это ≈76 МБ — быстро): `admin/`, `catalog/`,
`system/`, `yaorder/`, `inwidget/`, файлы корня. Это и есть полный код-бекап.

Хранение бекапов: локально у Максима; копию архива на хостинге держать ВЫШЕ
корня сайта (домашний каталог), не в public root.

## 4. Выкладка на хостинг

1. **FTP**: загрузить `eridanus-deploy-YYYYMMDD.tar.gz` в корень сайта
   (рядом с `index.php`).
2. **Файловый менеджер**: переименовать `system/storage/modification` →
   `system/storage/modification-backup-YYYYMMDD`. Это важно: простая распаковка
   поверх оставила бы старые прод-тени, отсутствующие в git (лишние = лишние
   активные подмены). Плюс это мгновенный откат теней.
3. **Файловый менеджер**: извлечь архив в корень сайта (с перезаписью
   существующих файлов). Извлечение серверное — лимитов PHP нет.
4. **Удалить `eridanus-deploy-*.tar.gz` из корня** — не оставлять архив
   публично скачиваемым. Архив бекапа кода из п. 2.2 перенести выше корня
   или скачать и удалить.
5. **Права**: выделить всё в корне → атрибуты: каталоги 755, файлы 644
   (ISPmgr обычно ставит владельца правильно сам). Веб-серверу нужна запись в
   `system/storage/{cache,logs,session,upload}` и `/image/`.
6. **Проверки окружения**:
   - папка админки на проде называется `admin/` (если переименована — файлы
     из пакета легли в `admin/`, сообщить агенту для корректировки);
   - версия PHP сайта (ISPmgr → WWW-домены → PHP): оставить текущую рабочую;
     НЕ переключать на 8.x — OpenCart 3.0.3.2 и модули с ней несовместимы;
   - витрина и админка открываются (не 500). При 500 — смотреть
     `system/storage/logs/error.log` файловым менеджером.
7. Сразу включить обслуживание: Система → Настройки → магазин → «Обслуживание»
   = Вкл (покупатели не увидят промежуточное состояние) — выключить после
   smoke-теста.

Откат кода: `modification-backup-YYYYMMDD` переименовать обратно +
распаковать `code-backup-*.zip` поверх; БД — дамп из п. 2.1.

### 6.5 Simple (чекаут)

1. Экспорт с dev (в админке dev, будучи залогиненным):
   `index.php?route=extension/module/simple/settings&user_token=...` — сохранить
   тело (JSON-массив с одним объектом). Резерв:
   `.agents/analysis/1.17-simple-settings-repaired.json`.
2. Импорт на прод: `POST index.php?route=extension/module/simple/settings`
   **form-urlencoded**, поле `settings=JSON.stringify([объект])` (формат
   vue-resource; JSON-тело запроса ОЧИЩАЕТ настройки!). Можно из консоли
   браузера на открытой странице прод-админки (`fetch` с сессией).
3. Контроль: повторный GET того же роута возвращает массив с объектом,
   а не `[null]`/`[[]]`.
4. Вписать **боевой ключ Simple** (Б1) в поле лицензии. Если форма не принимает
   (артефакт активации, как на dev в 1.19) — точечный UPDATE `simple_license` +
   очистить `system/storage/cache` и `session`.
5. Проверить: вкладка настроек открывается, шаблон одной колонки
   (`checkout[0].steps[0].template` из 1.13), ПВЗ-набор полей `apiship.point*|`,
   `cod` в списке оплат наложки.

### 6.6 Почта (System → Settings → Mail)

### 6.7 Cron — ISPmgr «Планировщик»

ISPmgr → Инструменты → Планировщик → Добавить, две задачи, интервал 5 мин
(«*/5» в минутах):

```
wget -qO- 'https://eridanus.ru/index.php?route=extension/shipping/apiship/export_orders&key=<cron_key>' >/dev/null 2>&1
wget -qO- 'https://eridanus.ru/index.php?route=extension/shipping/apiship/import_orders&key=<cron_key>' >/dev/null 2>&1
```

URL-ы с ключом — готовые в настройках модуля ApiShip. Если `wget` на хостинге
нет — `curl -s '...'` или внешний cron-сервис (cron-job.org) на те же URL.
Без cron статусы заказов из ApiShip не подтягиваются (1.7).
