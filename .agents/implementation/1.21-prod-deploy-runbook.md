## 1. Что переносится и что НЕ переносится

**Переносится из git (main, свежий HEAD на момент выкладки):**
- код OpenCart 3.0.3.2 + модули (Simple 4.11.9, ApiShip 1.2, avail, Measoft и др.);
- патченные оригиналы (валидация ПВЗ/адреса 1.23, availpro-патчи 1.18, seo_url и др.);
- `system/storage/vendor/` (код фреймворка — обязателен);
- тени `system/storage/modification/**` — РАБОЧИЙ набор (git add -f), кнопкой
  Refresh не воспроизводится (аудит 1.15);
- статика корня (robots.txt и пр.).

**НЕ переносится (на проде остаётся своё):**
- `config.php`, `admin/config.php`, `php.ini` — продовые;
- `.htaccess` — продовый (не включаем в пакет; сравнить с git при желании);
- `/image/` (29 ГБ) — уже на проде;
- БД — на проде своя, живые заказы; из dev переносятся ТОЛЬКО настройки (раздел 6);
- runtime-каталоги `system/storage/{cache,logs,session,upload}` — содержимое продовое;
- **на прод не копировать**: `adminer-*.php`, `user.php`, `phpinfo.php`, `wldb.php`,
  `fP46*.php`, `.agents/`, `.secrets/`, `agent-deploy-kit/`, `graphify-out/`,
  `storage79/`, `webstat/`, `.git*`, `AGENTS.md`.

Код без `/image/` — ≈76 МБ (сжатый пакет ≈20–30 МБ).

## 2. БЕКАП ПРОДА (до любых изменений)

### 2.1 База данных — phpMyAdmin

1. Войти в phpMyAdmin (из ISPmgr: «Базы данных» → phpMyAdmin, либо ссылка хостера).
2. Слева выбрать базу магазина (имя — из продового `config.php`, константа `DB_DATABASE`).
3. Верхнее меню «Экспорт»: способ «Обычный», все таблицы, формат SQL,
   сжатие gzip (или zip) → «Вперёд» — дамп скачается на локальную машину.
4. Проверить дамп: файл не 0 байт; внутри есть `CREATE TABLE` и данные заказов.

### 2.2 Файлы кода — файловый менеджер ISPmgr

Архивируем всё, КРОМЕ `/image/` (29 ГБ в квоту не влезет и не меняется):

1. Файловый менеджер → корень сайта.
2. Выделить все элементы корня, КРОМЕ `image` → «Упаковать в архив» →
   `code-backup-2026-10-28.zip` (название с датой).
3. Скачать архив по FTP на локальную машину — архив на том же диске НЕ бекап
   (но и не мешает: выкладка его не тронет).
4. Продублировать локально самое критичное (мелочь, на случай чего):
   `config.php`, `admin/config.php`, `php.ini`, `.htaccess`.
5. Проверить панельные бекапы: ISPmgr → «Инструменты» → «Резервные копии»
   (если есть в тарифе) — создать/зафиксировать точку восстановления.

### 2.3 Если архиватор панели не осилит

Скачать по FTP всё, кроме `image/` (это ≈76 МБ — быстро): `admin/`, `catalog/`,
`system/`, `yaorder/`, `inwidget/`, файлы корня. Это и есть полный код-бекап.

Хранение бекапов: локально у Максима; копию архива на хостинге держать ВЫШЕ
корня сайта (домашний каталог), не в public root.

## 3. Сборка пакета выкладки (локально, Git Bash, свежий клон)

```bash
git clone https://github.com/Modulecode-it/eridanus-opencart.git deploy
cd deploy
# убрать всё, что на прод не едет:
rm -rf .git .gitignore .gitkeep .graphifyignore .idea .agents agent-deploy-kit graphify-out storage79 webstat image
rm -rf system/storage/cache system/storage/logs system/storage/session system/storage/upload
rm -f config.php admin/config.php php.ini .htaccess .htaccess~ AGENTS.md
rm -f adminer-4.7.3-mysql.php user.php phpinfo.php wldb.php fP46rbbUAI3e2VFVpuhaTGcYUIHmjxGodAjuBkf2.php
# упаковать:

```

Контроль пакета: распаковать локально во временную папку и убедиться, что
НЕТ `config.php`, `adminer*`, `.git/`, `image/`; ЕСТЬ `system/storage/vendor/`
и заполненный `system/storage/modification/`.

## 4. Выкладка на хостинг

1. **FTP**: загрузить `eridanus-deploy-YYYYMMDD.tar.gz` в корень сайта
   (рядом с `index.php`).
2. **Файловый менеджер**: переименовать `system/storage/modification` →
   `system/storage/modification-backup-YYYYMMDD`. Это важно: простая распаковка
   поверх оставила бы старые прод-тени, отсутствующие в git (лишние = лишние
   активные подмены). Плюс это мгновенный откат теней.
3. **Файловый менеджер**: извлечь архив в корень сайта (с перезаписью
   существующих файлов). Извлечение серверное — лимитов PHP нет.
4. **Удалить `eridanus-deploy-*.tar.gz` из корня** — не оставлять архив
   публично скачиваемым. Архив бекапа кода из п. 2.2 перенести выше корня
   или скачать и удалить.
5. **Права**: выделить всё в корне → атрибуты: каталоги 755, файлы 644
   (ISPmgr обычно ставит владельца правильно сам). Веб-серверу нужна запись в
   `system/storage/{cache,logs,session,upload}` и `/image/`.
6. **Проверки окружения**:
   - папка админки на проде называется `admin/` (если переименована — файлы
     из пакета легли в `admin/`, сообщить агенту для корректировки);
   - версия PHP сайта (ISPmgr → WWW-домены → PHP): оставить текущую рабочую;
     НЕ переключать на 8.x — OpenCart 3.0.3.2 и модули с ней несовместимы;
   - витрина и админка открываются (не 500). При 500 — смотреть
     `system/storage/logs/error.log` файловым менеджером.
7. Сразу включить обслуживание: Система → Настройки → магазин → «Обслуживание»
   = Вкл (покупатели не увидят промежуточное состояние) — выключить после
   smoke-теста.

Откат кода: `modification-backup-YYYYMMDD` переименовать обратно +
распаковать `code-backup-*.zip` поверх; БД — дамп из п. 2.1.

## 5. Запреты (нарушение = падение прода)

1. **НЕ нажимать Refresh (Обновить) в Модификаторах** — аудит 1.15: даст ~204
   лишних файла (Filterit/optimblog/Yandex_beru, тени выключенных модов);
   рабочий набор теней приехал из git (раздел 4 п.2–3).
2. **НЕ массово импортировать `oc_setting`** (полный дамп через
   `route=tool/backup/import` или phpMyAdmin «Импорт» всей таблицы) — портит
   26КБ JSON `simple_settings` (инцидент 1.17). Только точечные однострочные
   INSERT/UPDATE (раздел 6) или API/формы модулей.
3. **НЕ переносить storage** через окно безопасности админки «перенести
   storage» (инцидент 1.19: warnings ломают заголовки; откат — runbook
   `implementation/1.19-storage-move-incident.md`).
4. **НЕ копировать на прод** служебные файлы (раздел 1), **НЕ заливать**
   дамп dev-БД в прод-БД (живые заказы!).

## 6. Установка модулей и перенос настроек

### 6.1 Таблицы модулей (в прод-БД их нет)

Install-методы идемпотентны (`CREATE TABLE IF NOT EXISTS`). В прод-админке
(Extensions → соотв. раздел → **Install**, НЕ Extension Installer — файлы уже
на месте):

| Модуль | Раздел | Что создаёт install() |
|---|---|---|
| Simple (4.11.9) | Extensions → Modules → Simple | `simple_custom_fields`, `address_simple_fields`, `order_simple_fields`, `simple_cart` |
| ApiShip (1.2) | Extensions → Shipping → ApiShip | `apiship_order`, `apiship_order_status` |
| avail | Extensions → Modules → «Уведомить о наличии» | `avail`, `avail_options` |

### 6.2 Перенос настроек — правила

- **Запрещён** массовый импорт `oc_setting` (п. 5.2).
- Новые ключи (на проде отсутствуют) → **INSERT**; существующие → **UPDATE**.
  В phpMyAdmin перед INSERT проверить наличие: `SELECT * FROM oc_setting WHERE `key` = '...'`.
- ⚠️ SQL-литерал: `\u0421` пишется как `\\u0421` (одинарный `\u` теряет
  бэкслеш — 1.20). У `module_avail_status` дублей не плодить (на dev было 3 —
  переносить одно значение).
- Simple — только через API модуля (6.5), не SQL.

### 6.4 Прочие UPDATE (ключи на проде уже есть)

```sql
UPDATE oc_setting SET value = '1'  WHERE `key` = 'payment_cod_order_status_id'; -- COD → «Ожидание»
UPDATE oc_setting SET value = '0'  WHERE `key` = 'shipping_flat_status';
UPDATE oc_setting SET value = '0'  WHERE `key` = 'shipping_pickup_status';
UPDATE oc_setting SET value = '1'  WHERE `key` = 'module_avail_status';
```

avail (привести к dev-значениям из 1.20, сравнив с dev): `avail_text[ru][button_avail]`
= «Сообщить о поступлении», фон/рамка `229ac8`, текст кнопки `ffffff`, классы
`btn btn-primary btn-lg btn-block` (карточка) / `btn btn-primary` (листинги);
CSS «вровень с Купить» уже в коде (`availability.css`). Лицензия avail доменная:
на eridanus.ru активация должна пройти (на dev принципиально не проходила — 1.17).
Measoft на проде не установлен — отключать нечего (не трогать).

### 6.5 Simple (чекаут)

1. Экспорт с dev (в админке dev, будучи залогиненным):
   `index.php?route=extension/module/simple/settings&user_token=...` — сохранить
   тело (JSON-массив с одним объектом). Резерв:
   `.agents/analysis/1.17-simple-settings-repaired.json`.
2. Импорт на прод: `POST index.php?route=extension/module/simple/settings`
   **form-urlencoded**, поле `settings=JSON.stringify([объект])` (формат
   vue-resource; JSON-тело запроса ОЧИЩАЕТ настройки!). Можно из консоли
   браузера на открытой странице прод-админки (`fetch` с сессией).
3. Контроль: повторный GET того же роута возвращает массив с объектом,
   а не `[null]`/`[[]]`.
4. Вписать **боевой ключ Simple** (Б1) в поле лицензии. Если форма не принимает
   (артефакт активации, как на dev в 1.19) — точечный UPDATE `simple_license` +
   очистить `system/storage/cache` и `session`.
5. Проверить: вкладка настроек открывается, шаблон одной колонки
   (`checkout[0].steps[0].template` из 1.13), ПВЗ-набор полей `apiship.point*|`,
   `cod` в списке оплат наложки.

### 6.6 Почта (System → Settings → Mail)

SMTP, `info@eridanus.ru`, креды Яндекса (Б3), порт/шифрование по аккаунту
(обычно 465 SSL). Проверка — письмо восстановления пароля (раздел 8).

### 6.7 Cron — ISPmgr «Планировщик»

ISPmgr → Инструменты → Планировщик → Добавить, две задачи, интервал 5 мин
(«*/5» в минутах):

```
wget -qO- 'https://eridanus.ru/index.php?route=extension/shipping/apiship/export_orders&key=<cron_key>' >/dev/null 2>&1
wget -qO- 'https://eridanus.ru/index.php?route=extension/shipping/apiship/import_orders&key=<cron_key>' >/dev/null 2>&1
```

URL-ы с ключом — готовые в настройках модуля ApiShip. Если `wget` на хостинге
нет — `curl -s '...'` или внешний cron-сервис (cron-job.org) на те же URL.
Без cron статусы заказов из ApiShip не подтягиваются (1.7).

## 8. Smoke-тест на проде

1. Витрина: главная, категория (сортировка), карточка товара — без 500.
2. Корзина с товаром: НЕТ блока «Что бы вы хотели сделать дальше?» (1.22).
3. Кнопки «Сообщить о поступлении» — вровень с «Купить» (десктоп+мобайл,
   листинг+карточка), клик открывает модалку.
4. Чекаут: Simple одной колонкой (не штатный!) — Покупатель → Адрес →
   «Доставка и оплата» → Комментарий; котировки ПВЗ и курьер появляются
   (Яндекс сразу; 5Пост — после активации тарифов x5).
5. Карта ПВЗ открывается за секунды, пункт выбирается, адрес пункта
   появляется в названии способа доставки.
6. Негативные проверки (1.23): «самовывоз» без пункта → «Пожалуйста, выберите
   ПВЗ!», заказ НЕ создаётся; курьер без адреса → «Пожалуйста, укажите адрес
   доставки!», заказ НЕ создаётся.
7. Скорость: первое открытие чекаута по городу ~3 с, повторы 1–3 с; в
   `system/storage/cache/` появляются `apiship.*.cache`.
8. Тест-заказ (согласованный, помечен TEST): наложка через ПВЗ → заказ в
   админке → панель ApiShip → выгрузка → в ЛК apiship.ru заявка с треком.
9. Письма: подтверждение заказа и восстановление пароля доходят (SMTP).
10. Админка: вход, список заказов, экспорт/накладные ApiShip в карточке заказа.
