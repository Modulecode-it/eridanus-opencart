# AGENTS.md

## Система памяти агента

Этот проект использует систему памяти `.agents/` для документирования рабочего процесса агента.

Для каждой новой нетривиальной задачи:
- Перед широким анализом или реализацией прочитать `.agents/README.md`, `.agents/CORE.md`, `.agents/PROJECT_STRUCTURE.md` и `.agents/STACK.md`.
- Использовать `.agents/CHECKLISTS.md` как чек-лист задачи.
- Создавать или обновлять документацию задачи с одним общим task-id в:
  - `.agents/specs/`
  - `.agents/analysis/`
  - `.agents/implementation/`
  - `.agents/reports/`
- Поддерживать актуальными `.agents/INDEX.md` (реестр задач) и `.agents/CHANGELOG.md` (история системы памяти).
- Новые и обновляемые документы `.agents` писать на русском, оставляя без перевода технические идентификаторы, пути, роуты, код, SQL, XML, фрагменты PHP/Twig/JS и значения конфигов.
- Не хранить в `.agents` секреты, токены, полные логи, данные клиентов и доступы к окружениям.
- Перед завершением обновить `.agents`, если задача выявила долговечное знание о проекте (таблица маршрутизации — в `.agents/CORE.md`: PROJECT_STRUCTURE / STACK / RULES / CHECKLISTS / ADR).

## graphify

В этом проекте есть граф знаний в `graphify-out/`: god-узлы, структура сообществ и межфайловые связи.

Когда пользователь вводит `/graphify`, вызови инструмент `skill` с `skill: "graphify"` прежде чем делать что-либо ещё.

Правила:
- По вопросам о кодовой базе сначала запускай `graphify query "<вопрос>"`, если существует `graphify-out/graph.json`. Для связей используй `graphify path "<A>" "<B>"`, для фокусированных концепций — `graphify explain "<концепция>"`. Они возвращают ограниченный подграф, обычно намного меньший, чем GRAPH_REPORT.md или сырой вывод grep.
- «Грязные» файлы `graphify-out/` после хуков или инкрементальных обновлений — норма; грязные файлы графа не причина пропускать graphify. Пропускай graphify, только если задача касается устаревшего или некорректного вывода графа либо пользователь явно просит его не использовать.
- Если существует `graphify-out/wiki/index.md`, используй его для широкой навигации вместо сырого просмотра исходников.
- Читай `graphify-out/GRAPH_REPORT.md` только для широкого ревью архитектуры или когда query/path/explain не дают достаточного контекста.
- После изменения кода запускай `graphify update .`, чтобы граф оставался актуальным (только AST, без затрат на API).

## ⚠️ Главное правило: сайт — dev-копия на сервере, локальной среды запуска нет

Сайт (`eridanus.dev.modulecode.ru`) — **dev-копия**, крутится на удалённом dev-сервере в Docker-проекте (там же другие сайты). Локально нет PHP/БД/веб-сервера.

**НЕ запускай локально** (PHP и серверная архитектура):
- `php -S`, попытки поднять OpenCart, `mysql`/`mariadb`, Apache/Nginx.
- Всё, что требует поднятия OpenCart/БД/веб-сервера.

**Браузерный доступ к dev-сайту — РАЗРЕШЁН** (подтверждено владельцем, задача 0.5):
- Через плагин browser-use можно открывать витрину и админку `eridanus.dev.modulecode.ru`: настройка модулей, проверки, тестовые заказы, скриншоты.
- Креды dev-админки (отдельный AI-пользователь) — в `.secrets/dev-admin.md`; папка `.secrets/` в `.gitignore` (репо пушится на GitHub), в `.agents` секреты не хранить.
- **База — копия боевой**: действия с реальными заказами/клиентами — только с явного одобрения пользователя. Тестовые сущности помечать как тестовые.
- **Перед важными/разрушающими операциями** (удаление, установка/удаление модулей, массовые правки, SQL) — сначала предложить бекап (System → Maintenance → Backup → Export, либо Adminer) и дождаться подтверждения. Подробности — `.agents/STACK.md`, секция «Браузерный Доступ к Dev-Сайту (AI)».
- **SSH к серверу нет и не будет** (на нём другие сайты): серверные шаги (`git pull` на сервере, cron, рестарты) выполняет пользователь.

**МОЖНО локально** (статические и не-PHP проверки, не запускающие приложение):
- `php -l <file>` — если PHP есть локально как бинарник (на этой машине его нет); это lint синтаксиса, а не запуск приложения.
- `bash -n`/`shellcheck` для bash-скриптов; `eslint`/`prettier --check`/`markdownlint` для не-PHP кода и разметки; валидаторы JSON/XML/YAML (в т.ч. проверка `.ocmod.xml` разбором текста); Twig-шаблоны — разбор текстом, без рендера.
- `graphify update .` / `graphify query ...` (Python, AST-only, без API-цены).
- Проверка regex, имён файлов, целостности ссылок, чтение кода/типов/маршрутов как замена запуску.

Код правь через чтение кода/типов/маршрутов. Runtime-проверки PHP/БД/витрины — через браузер на dev-сайте; серверные шаги (SSH/cron) — передавай пользователю (см. скилл `no-local-testing`, `.agents/skills/no-local-testing/SKILL.md`). Не-PHP проверки прогоняй локально и отмечай в отчёте, что именно проверено.
